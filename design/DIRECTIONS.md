# 方向探索：Keel 身份与访问

> change：`keel-bot-identity-access` · P0 设计
> 流程：`world-class-designer` v0.5.2（Stage 0 人物/故事 → T0 品类地板 → T1 方向引擎 + seed challenger → 差异门 → 收敛）
> 结论：**推荐方向 B「账簿」**；A「控制台」保留为 baseline；C「任务简报」保留为挑战者并吸收其「待我处理」；D 为 seed 探针，不进入实现。
> 既有 `PRODUCT-DESIGN.md` 的对象模型、旅程、五态、文案继续有效；本文改的是**结构、层级与导航壳**。

---

## 0. 为什么重做

Owner 2026-11-21 反馈：现有界面不满意，不是逐条改，而是「用 OpenDesign 好好做」。这意味着：

- **旧 Agent/团队设置页不是基线**。它的左栏 + 卡片堆叠 + 多节滚动是「设置中心」的惯性，不是 AI 员工组织的必然结构。
- **不能交换皮稿**。只把旧页面塞进新壳、只换颜色/圆角/间距，不构成方向。
- **产品感优先**。首屏目的与主操作、渐进披露、引导式空态、五态、权限不足解释、人话文案，先于组件细节。
- **设计语言不变**。shadcn 官方件 + solid-glass + `web/theme.json` 令牌 + lucide 单色；变的是层级、留白、字体尺度、信息密度与页面结构。

因此本文先做人物与故事（Stage 0），再做品类地板（T0），再做三个真正不同的方向 + 一个 seed 挑战者（T1），最后给推荐与取舍。

## 1. Stage 0：人物与故事（先于功能与视觉）

### 1.1 收敛到三个人物 + 一个非 UI 行动者

> 规则：一个界面最多承载 2–3 个角色；更多角色应拆界面，而不是堆在同一屏。这里把「部署管理员 / 团队管理员 / 普通成员」收敛为三条故事线；Bot 不是 UI 用户，它的体验发生在工具结果与审计里。

| 人物 | 是谁 | 在 Keel 里的位置 | 主要界面 |
|---|---|---|---|
| **李娜 · 团队管理员** | 客服主管，不写代码；对业务极熟，对权限模型只懂「谁能看什么」 | 租户内；有账号、权限组、Bot、团队的管理能力 | 身份 / 员工 / 团队 |
| **王强 · 部署管理员** | 部署 Owner，凌晨会被叫醒；熟悉审计与密钥 | 部署级超管；可跨租户 | 记录 / 运行 / 员工密钥 |
| **陈墨 · 普通成员** | 一线客服，第一次用 Keel；只想赶紧解决客户问题 | 租户内；只看自己被共享的会话与被授予的 Bot | 工作区 |
| **管家 Bot** | 非 UI 行动者；高权限 AI 员工 | 独立 Bot 账号；不是超管 | 会话里的工具卡 + 审计 + DAG |

### 1.2 新手故事与专家故事（用用户语言，不用界面词汇）

**李娜 · 新手故事（周一 9:40，新同事入职）**
> 小周 10 点要接手客服会话，但不能看财务。我要在站会前让他能干活。我打开 Keel，想先找到小周这个人，把他放进「客服」那一组，然后看一眼他实际能做什么；最后去团队页把客服团队跑起来。

- 交互预算：≤5 个动作（打开身份 → 搜小周 → 加入客服组 → 保存 → 去团队启动）。
- 闭环：加入后必须能看到「有效能力」变化；保存后必须看到「已写入审计」的确认。
- 安全门：保存权限变更是显式动作，不能被自动保存吞掉。

**李娜 · 专家故事（周三 16:10，临时加一个调用权）**
> 客服组要临时能用「订单查询」。我不想翻 24 个能力，只想搜「订单查询」或「调用 Bot」，把范围改成他们需要的，保存，看到影响 8 个人。

- 交互预算：≤3 个动作（搜能力 → 改范围 → 保存）。
- 闭环：保存后成员的下一次操作立即生效；页面上能看到「影响 8 位成员」。
- 审计字段：谁、何时、改了哪几项、旧值/新值。

**王强 · 专家故事（凌晨 2:10，告警）**
> 告警说一个 Bot 在大量读密钥。我要在 30 秒内找到它的调用链，吊销它的密钥，确认它属于谁、还碰过什么。

- 交互预算：≤3 个动作（记录里搜 Bot → 打开运行/事件 → 吊销密钥）。
- 闭环：吊销后下一次调用 401；运行页显示「已失去调用权」；审计有记录。
- 审计字段：调用者、被调用 Bot、结果、时间、来源。

**陈墨 · 新手故事（下午 16:00，客户催退款）**
> 客户在催退款。我要找一个能查订单的 Bot，问一句，拿到能直接发给客户的回复；不想看到别人的会话。

- 交互预算：≤3 个动作（打开工作区 → 选共享/可调用 Bot → 发送）。
- 闭环：回答里能看出它查了订单；如果它越权，告诉我缺什么，而不是静默失败。
- 安全门：他看不到未被共享的会话；共享被撤销时 2 秒内变只读。

**管家 Bot · 非 UI 故事**
> 用户说「帮我组建客服团队并跑起来」。管家用与李娜完全相同的 API 创建 3 个 Bot、1 个团队、1 个权限组；越权时停下来求助；全过程可在 DAG/审计里查到。

### 1.3 沙盒：功能块、三轮放置、停止条件

**v1 功能块清单（未判断，先全量）**

登录/首次设置/强制改密；工作区会话列表；对话；共享给我；团队会话；Bot 列表；Bot 创建（身份/模型/工具/能力）；Bot 详情（概览/行为/权限/密钥/会话）；试跑；TeamBot 列表；TeamBot 编辑（Mission/Roster/队长/启动前检查/启动）；运行列表；DAG；节点检查器；账号列表；账号详情（概览/权限/Bot/会话/安全）；权限组列表；权限组编辑（矩阵/成员）；审计；设置；403；空/错/加载/断线。

**第 1 轮 · 李娜新手路径（入职）**

| 层 | 放回什么 | 理由 |
|---|---|---|
| 直接（首屏） | 身份章节的账号索引、搜索、加入组、组保存后的有效能力摘要 | 她 80% 的动作是「找人 → 给组 → 确认」 |
| 次要（≤2 击） | 团队索引 → 启动；员工索引 → 试跑 | 入职后紧接着要跑团队 |
| 深处 | 直接授权、密钥轮换、审计原始事件、跨租户 | 低频且高后果 |
| 删除 | 「共享中心」独立页、账号详情里的直接授权编辑器、团队权限页 | 与唯一真源冲突或概念不存在 |

**第 2 轮 · 王强专家路径（事故）**

| 层 | 放回什么 | 理由 |
|---|---|---|
| 直接 | 记录章节的搜索/筛选、运行泳道、节点检查器的「权限判定」 | 30 秒内定位 |
| 次要 | Bot 密钥页、账号详情安全页 | 吊销与归属 |
| 深处 | 原始事件字段、跨租户筛选、导出 | 事后取证 |
| 删除 | 每个页面各放一份「操作记录」 | 审计只有一个真源 |

**第 3 轮 · 陈墨新手路径（客户）**

| 层 | 放回什么 | 理由 |
|---|---|---|
| 直接 | 工作区「共享给我」、可调用 Bot 的选择、对话 | 他的全部任务 |
| 次要 | Bot 详情的只读能力说明 | 想知道「它为什么不能查」 |
| 深处 | 共享设置、权限解释 | 低频 |
| 删除 | 员工/团队/身份章节对他的曝光（无权限即隐藏） | 不让他误入管理面 |

**停止条件**：第 3 轮没有新增功能块，只发生层级调整；再走一轮不增不破 → persona-stable。记录为「沙盒稳定（3 轮）」。

## 2. T0：品类地板

**品类**：AI 员工的身份与访问控制台（账号、权限组、Bot、团队、运行、审计）。不是通用 SaaS 后台，也不是纯监控台。

**标杆（选最鲜明的，不选最有名的）**：Retool（agent 作为可授权对象 + Settings > Groups）、ClickHouse Agents（角色 + 资源 ACL + admin 权限分层）、Linear（工艺、密度、导航克制）。

**拆 Retool 的 8 个可见选择**：

| # | 它怎么做 | 为什么 | 我们 |
|---|---|---|---|
| 1 | 设置嵌在左栏底部，管理员进入一个独立模式 | 管理是低频、独立心智 | **换**：身份/团队/运行是一级章节，不藏进设置 |
| 2 | 组是授权单位，成员用表格批量管理 | 人比权限位多，组可复用 | **留**：权限组是唯一授权面 |
| 3 | 资源按类型分 tab（Agents / Tools / Resources） | 不同对象的权限语义不同 | **换**：我们用域 + 范围，不用资源类型 tab |
| 4 | 行内 checkbox / 下拉，密集表格 | 快速扫视与比较 | **留**：行内选择；**换**：范围是第二维，不用复选 |
| 5 | 中性底 + 一个强调色，管理面不抢内容 | 高后果界面应克制 | **留**：中性石墨 + 单一主操作 |
| 6 | 36–40px 行高，搜索在表上方 | 长列表可比较 | **留**：44px 行高 + 搜索优先 |
| 7 | 破坏性操作二次确认，审计独立 | 安全与追溯 | **留**：确认 + 审计唯一真源 |
| 8 | 卡片套卡片、蓝色强调、圆角面板 | 品牌身份，不是必然结构 | **不复制**：不做 Retool 撞脸；不用蓝色主色 |

**结论**：地板是「组为单位、搜索优先、密集可比较、审计独立、破坏性确认」。我们不继承的是「设置中心 + 左栏 + 卡片堆叠 + 蓝色强调」。方向必须在结构上偏离，而不是把地板刷成另一种颜色。

## 3. T2：调性五刻度（每条给证据）

| 刻度 | 取值 | 证据 | 可观察决定 |
|---|---|---|---|
| 能量 | 安静 | 身份/权限/审计是高后果、低娱乐场景；用户要判断，不要被刺激 | 强调色 ≤10% 面积；无渐变/发光；一个主操作/页 |
| 完成度 | 精致 | 已发布的 Keel 设计语言；用户每天长时间使用 | 1px 描边；对齐严格；阴影只给浮层；无手绘装饰 |
| 密度 | 中密（balanced-dense） | 李娜不是受训的操作员，不能按航空面板的密度设计；但她要一屏比较 20+ 能力 | 44px 行；12/13/14 字号；段间距 24/32；分组而非卡片堆叠 |
| 分量 | 中 | 深色底；正文 400；标题 500/600 | 不用细体；不用超粗标题；数字用 mono 但不抢正文 |
| 严肃度 | 庄重 | 审计、超管恢复、密钥、越权 | 圆角 6/12；无插画；动效只做状态反馈（120/180ms） |

**模糊词翻译**（若出现）：  
- 「高级」→ 3 级字号（10.5 / 13.5 / 24–32）、2 级圆角（6/12）、1 级阴影（仅浮层）、≤2 个语义色同时出现。  
- 「克制」→ 主操作每屏 1 个；强调色 ≤10%；无装饰性图标；空态不超过 3 行文案。  
- 「清晰」→ 每页一句目的；每个对象一个真源；每个动作有下一步。

## 4. T1：三个方向 + 一个 seed 挑战者

> 每个方向用不同引擎；不是同一套布局换颜色。每个方向注明 desktop / pad / mobile。
> 骨架先于文案；同一轮「双栏工作台」最多出现一次（A 用了，B/C 不用）。

### 方向 A · 控制台（Baseline）

| 项 | 内容 |
|---|---|
| 引擎 | 工作型骨架「对象 + 动作挨着」：列表与详情同屏，动作贴着对象 |
| 首屏骨架 | 左栏 232 + 内容；列表 360 + 详情；详情用页签 |
| 字体 | 20 标题 / 13 正文 / 11 标签；系统 sans |
| 色彩身份 | 石墨底 + 白色主操作 + 绿/蓝状态；最接近现有 Keel |
| 主视觉 | 无；靠表格与状态徽章 |
| 页面结构 | 工作区 / 员工 / 团队 / 管理 / 设置；管理内含账号、权限组、审计 |
| 记忆点 | Bot 详情的「账号上限 ∩ 工作范围 = 有效能力」三层块（李娜「他实际能做什么」的时刻） |
| Desktop | 左栏 + 列表 + 详情同屏 |
| Pad | 左栏折叠为 64 图标；列表 → 详情 drill-in |
| Mobile | 底部 4 tab；表格变卡片；详情整页 |
| 优点 | 熟悉、效率高、实现成本低；与现有壳最接近 |
| 缺点 | **就是品类套路**：左栏 + 列表/详情 + 卡片；与旧设置页同构；Owner 明确说不要换皮 |
| 结论 | 保留为 baseline，不作为推荐 |

### 方向 B · 账簿（推荐）

| 项 | 内容 |
|---|---|
| 引擎 | **他领域媒介**：一本有索引、页边、签记栏的账簿。身份是授予与归属的记录，审计是账本本身。 |
| 首屏骨架 | **顶部章节索引带 + 左侧页边（spine）+ 单页纸面（sheet）**；章节索引是 01 工作区 / 02 员工 / 03 团队 / 04 身份 / 05 记录；页边固定当前对象的身份、关键事实、主操作、章节内索引；纸面是连续的「带」（band），不是卡片。**身份例外**：桌面用 280 常驻索引列（账号默认 / 权限组子页），不做 drill-in。 |
| 字体 | 对象名 30–32（唯一 H1）；节标题 18–20；正文 13–14；元数据 12；mono key 11；标签 ≥11；禁止 10px 中文。字号对比比 A 更强，卡片更少。 |
| 色彩身份 | 中性石墨 + **琥珀只表示「未保存/待办/待签」**；白色主操作；风险用独立黄→红刻度；范围提升/新增用信息蓝。琥珀是本方向唯一的新鲜色，来自既有令牌。 |
| 主视觉 | **页边 + 签记条**：滚动长页时，页边始终告诉你「你在看谁、还剩什么」；保存时出现一条签记栏（谁、何时、改了什么）。身份章用 280 常驻索引列承担同样的「你在看谁」。 |
| 页面结构 | 章节 → 对象索引（一张账页）→ 对象页（页边 + 纸面）；无左栏、无卡片堆叠、无页签。**身份例外**：280 常驻索引列 + 纸面，账号默认、权限组为同一索引子页。 |
| 记忆点 | **签记条**（李娜保存权限时的「签名」时刻；王强事故后的「这笔账已记下」）。页边是它的常驻搭档。 |
| Desktop | 顶部章节带 56；页边 220；纸面 max 1040；签记条固定在纸面底部；身份 1440：280 索引 + 820 四列表；1024：全宽五列表 + 单搜索。 |
| Pad | 页边折叠为纸面上方的「对象摘要带」；章节带横向可滚；身份全宽五列表；运行泳道保留父条→子条失败边 + 顶部失败摘要 + 平板简化 + 检查器入口。 |
| Mobile | 章节带变「当前章节 + 切换」；页边变摘要卡；纸面单列；身份加「账号 / 权限组」segmented；运行时间线 + 检查器 Sheet + 停止二次确认；关键操作 ≥44px；Bot 能力页 44px 选择。 |
| 优点 | 与品类默认结构真正不同；身份/审计的「记录」心智成立；信息层级靠字号、留白与分隔线，不靠卡片；可容纳密集矩阵与长审计。 |
| 缺点 | 其他章节的 drill-in 仍多一次点击；纸面容易显得「文档化」；运行页泳道需要跨泳道边语法（已画通）。 |
| 缓解 | 页边顶部放「切换」搜索（1 击 + 输入）；索引页保留「最近」；身份章改常驻索引；泳道默认 + 图第二视图；边画不稳时切图默认。 |
| 结论 | **推荐**：B 做壳 + A 的常驻索引 + A 的分层 DAG 第二视图 + C 的「待我处理」窄带。 |

### 方向 C · 任务简报（挑战者）

| 项 | 内容 |
|---|---|
| 引擎 | **具体场景**：8:50 的客服交接台。屏幕上先回答「今天这台部署在做什么、什么需要人」。 |

## 6. 收敛：推荐 B，吸收 C 的队列

### 6.1 推荐理由（按证据，不按口味）

1. **它解决「不是换皮」**：B 的顶部章节带 + 页边 + 纸面带，与旧设置页的左栏 + 卡片堆叠是两套结构；同一份内容在 B 里靠字号、留白、分隔线组织。
2. **它符合对象语义**：身份是授予与归属的记录，审计是账本；「签记」把高后果动作变成可理解的承诺，而不是一个普通保存按钮。
3. **它容纳密集信息**：权限矩阵、审计、运行记录都能在「带 + 行 + 印章」里比较，不需要卡片套卡片。
4. **它保留 A 的效率**：页边的对象摘要 + 主操作，让「对象 + 动作」仍然挨着；身份章直接改成 280 常驻索引列，补足 drill-in 的成本。
5. **它吸收 C 的运营性**：在工作区与索引页顶部放一条「待我处理」，把越权、失败运行、缺 invoke 的成员前置；不把整个产品改成监控台。
6. **它通过视觉评审**：独立评审 7.5/10 YES WITH FIXES；P0/P1 已修（运行页跨泳道边与失败焦点、字号地板、权限表四列、主操作随状态、琥珀语义、设置入口、五态/1024/768）。

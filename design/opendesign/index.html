00 · 信息架构（推荐方向 B）

五章一本账，对象各有一页

顶部章节索引带代替左栏；每章先是一张对象索引（账页），点进对象后由页边固定身份、关键事实与主操作。身份与记录是同一本账的两面：一个记授予，一个记发生。设置仍在右上角，只放部署级配置。

01命令是主内容

没有管理员时，最需要的是「下一步命令」，不是一句 503。命令块带复制，口令字段只有一个。

02错误不区分账号

「用户名或密码不正确」统一说法；限速与锁定单独说清等待时间，不暗示账号是否存在。

03强制改密有理由

不说「系统要求」，说「初始化密码可能经过他人之手」。这是用户能理解的信任时刻。

A2 · 账号（baseline）

列表回答「有谁」，详情回答「他能做什么」

账号是权限主体。详情页的权限页签只读：有效能力按域分组，来源写到具体权限组；改权限永远回权限组，避免同一个人有两个授权入口。

01权限只读

账号详情展示有效能力与来源，但不做直接授权编辑。一个概念（给权限）只有一个入口（权限组）。

02类型是标签不是分支

「人 / Bot / 服务」只用于说明文案；按钮出现与否由 can() 决定，不由 kind 决定。A baseline 的状态列仍混合在线/最近活动；B 的 1024 帧已拆成状态 / 最近活动两列。

03危险操作降权

「禁用」是 ghost 文本按钮，主操作是「加入权限组」。禁用对话框会列出会话吊销与密钥失效的后果。

A3 · 权限组（baseline）

一张可比较的能力表，而不是散落的开关

按域分组、每行一个能力、每行选一个范围。范围是独立的第二维，不用三态复选硬塞。授予者只能授出自己持有的范围，超出的选项直接禁用并写明原因。

08 · 评审选择点

需要 Owner 拍板的五件事

方向与取舍见 design/DIRECTIONS.md，验收映射见 design/REVIEW.md。未拍板前，L5 不应进入实现。

01方向：B / C / A

推荐 B 账簿；C 任务简报是挑战者；A 控制台是 baseline。不是配色选择，是结构选择。

02章节命名

身份（账号 + 权限组）与 记录（审计）；备选「访问 / 审计」。

03运行视图

泳道默认 + 「图」切换（推荐），还是节点图默认 + 「泳道」切换。

04索引形态

drill-in + 页边快速切换（推荐），还是常驻索引列（更像 A 的双栏）。

05吸收「待我处理」

作为工作区/索引页顶部窄带，还是独立章节；推荐前者，不做监控台。

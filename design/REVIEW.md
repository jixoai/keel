## 1. 三个关键设计决策

### D1 · 方向：账簿（B）作为主结构，控制台（A）只做 baseline

| 选项 | 结构 | 优点 | 缺点 |
|---|---|---|---|
| **A 控制台** | 左栏 + 列表/详情 + 页签 | 熟悉、效率高、实现成本低 | 品类默认；与旧设置页同构；Owner 明确不要换皮 |
| **B 账簿**（推荐） | 顶部章节带 + 页边 + 纸面带 + 签记 | 结构真正不同；身份/审计的「记录」心智成立；密集信息可比较 | drill-in 多一次点击；纸面易显文档化；运行页要新语法 |
| **C 任务简报** | 待办 + 运行 + 名册横条 | 最像 AI 员工操作台；状态前置；直接服务管家/团队场景 | 新部署首页空；设置路径被降级；验收的线性 IA 不直观 |

**推荐 B**，理由按证据排序：

1. Owner 反馈「旧界面不满意、不要换皮」——A 是旧壳的扩展，不能作为答案。
2. 身份与访问的核心心智是**记录**：谁被授予什么、谁做了什么。账簿的页边 + 签记比卡片堆叠更贴语义。
3. 权限矩阵、审计、运行都是长表；B 的「带 + 行 + 印章」比卡片套卡片更能比较，也更安静。
4. B 保留 A 的效率：页边把对象身份与主操作固定在旁边；索引页 + 页边「切换」补足 drill-in 成本。
5. C 的「待我处理」被吸收进 B 的工作区与索引页顶部，不放弃运营性。

**被放弃**：A 作为最终方案；C 的整体 IA；D 索引表单（只做 divergence probe）；左栏图标导航；卡片套卡片；对象页页签；独立的「共享中心」；每页各放一份操作记录。

### D2 · 授权只从权限组来；范围是第二维；保存是签记

| 选项 | 做法 | 判断 |
|---|---|---|
| **组唯一授权面**（推荐） | 账号页的能力只读；加权限 = 加入组；组页用「每 key 选范围」+ 本次变更 diff + 签记条 | 一个概念一个入口；可审计；符合 `grant ⊆ own` |
| 账号页直接授权 | 账号页也能逐项授权 | 两个授权入口；审计难追；不采纳 |
| 三态复选矩阵 | 每个 key 一个复选框 | scope 有四档，复选表达不了；不采纳 |
| 角色预设 | 只给「管理员/成员」预设 | 能力目录约 40 项，预设不够；保留为「模板/另存为副本」，不是唯一方式 |

**界面规则**：

- 范围选项：`未授予 / 仅自己 / 本团队 / 整个租户 / 全部`；超出授予者自身范围的选项禁用并写「你最多可授『本团队』」。
- 保存前显示「本次变更」3–N 行（旧值 → 新值），并写明影响人数与生效时机。
- 签记条：署名 + 生效说明（保存后写入 05 记录）+「保存并签记」。
- 内置组只读；`super-admin` 固定全部能力；其他内置组「另存为副本」。
- 账号页不提供直接授权编辑；只读展示有效能力与来源。

### D3 · 运行：泳道默认 + 「图」切换；移动端时间线

| 选项 | 做法 | 判断 |
|---|---|---|
| **泳道默认 + 图切换**（推荐） | 横轴时间、纵轴执行者；条 = Session；细线 = 调用；红虚线 = 拒绝；检查器贴右 | 回答「谁在什么时候做了什么」；失败与时序一眼可见 |
| 节点图默认 | 分层节点 + 边 | 回答「谁调用了谁」更直接，但时序与拒绝原因要下钻；保留为切换 |
| 力导向图 | 自动布局 | 不可读、不可预测；不采纳 |
| 纯表格 | 运行事件表 | 没有空间关系；只作为底部「最近事件」补充 |

**理由**：王强的 30 秒定位故事要的是「谁在什么时候调用了谁、哪里被拒」，不是拓扑美学。泳道是同一账本的时间投影；「图」是拓扑投影，不产生第二真源。移动端不硬塞图：时间线 + 检查器 Sheet；「图」进全屏 Sheet。

## 2. 需要拍板的点（≤5）

| # | 问题 | 选项 | 推荐 | 影响 |
|---|---|---|---|---|
| 1 | **主方向** | A 控制台 / B 账簿 / C 任务简报 | **B** | 决定 L5 的整个壳与页面结构；A 需接受「与旧壳同构」 |
| 2 | **章节命名** | `身份` + `记录` / `访问` + `审计` / `成员与权限` + `审计` | **身份 / 记录** | 导航文案与权限矩阵的标题；影响用户能否预测「去哪配权限」 |
| 3 | **运行默认视图** | 泳道默认 + 图切换 / 图默认 + 泳道切换 | **泳道默认** | 决定 DAG 的实现顺序与默认截图；验收口径「DAG 可查看」两种都满足 |
| 4 | **索引形态** | drill-in + 页边切换 / 常驻索引列 | **drill-in + 页边切换** | 决定专家切换成本；常驻列更像 A 的双栏，结构纯度下降 |
| 5 | **「待我处理」** | 工作区/索引页顶部窄带 / 独立章节 / 不做 | **顶部窄带** | 决定是否吸收 C 的运营性；独立章节会让 IA 多一个监控面 |

> 拍板方式：回复编号 + 选项（如「1 B，2 身份/记录，3 泳道，4 drill-in，5 窄带」）。未拍板前 L5 不进入实现。

## 5. 与既有标准的张力（需回写/裁决）

1. **`fde2e-frontend-standards` 说「设计语言不变」**：本设计理解为组件/令牌/图标同源，不限制结构、层级、密度重做；若 Owner 认为旧布局也属于「设计语言」，B 需降级为 A 的变体。已列为拍板点 1。
2. **tasks.md A4 说「设置页：账号 / 权限组 / Bot / TeamBot」**：B 把身份/员工/团队提为章节，设置只保留部署配置。这是 P0 产品设计对实现清单的修正；需 MainAgent 在任务板更新措辞，不改 OpenSpec 设计文档。
3. **`bot.create` vs `bot.manage`**：`spec.md` 的管家场景用 `bot.create`，`design.md` §3.1 的 key 列表用 `bot.manage`。设计用「管理 Bot」作为能力名，不绑定具体 key；registry 冻结时需二选一或拆细。
4. **`bot.invoke` 未出现在 design.md §3.1 的 key 列表**：但它在 proposal/design/spec 的正文里是核心高危 key。设计按 `bot.invoke` 表达；registry 必须收录。
5. **章节带用 `Tabs variant="line"` 作为导航原语**：kit 暂无 `NavigationMenu`；这是临时映射，不新增手写组件。若 L5 认为语义不对，先在 kit 收编 `NavigationMenu` 再实现。
6. **375 宽 5 个 tab**：每项约 78px，中文 2–3 字可放下；若真实字体/本地化导致折行，改成 4 tab + 「更多」或在 375 用「当前章节 + 切换」的顶栏。验收时需实测。

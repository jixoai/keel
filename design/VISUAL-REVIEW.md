# Visual review (independent, fresh context)

> 评审对象：`design/opendesign/index.html` 的 14 张 1440 宽截图（`/tmp/keel-sec-00..13.png`）。
> 评审只拿图，不看实现。日期：2026-11-22。
> 结论：**B 账簿 = YES WITH FIXES；总分 7.5/10**。B 是真结构（约七成可直接实现），但运行页仍是“账本的插图”。

## 1. 方向判断

- **A 控制台**：成熟后台，最线性；但品类默认，与旧设置页同构，不作为最终方向。
- **B 账簿（推荐）**：页边固定对象身份 + 章/对象/节 + 三层能力 + 登记条；去掉“账本”隐喻仍成立，是真结构。
- **C 任务简报**：概念最强但只有线框；其“待办/失败前置”应被 B 工作区吸收，不做常驻监控台。
- **D 索引表单**：seed probe，不参与实现。

建议：**B 做壳**，吸收 A 的常驻索引与 DAG 第二视图、C 的待办窄带。

## 2. P0（实现前必须修）

1. **运行页没有画调用关系与失败焦点**（`keel-sec-04.png`）：
   - 泳道之间没有调用边，只有 bar 上方 9px 小字；父子 Agent 被误读为并行任务。
   - 唯一失败（售后升级 403）默认不在检查器；403 只是 30px 小红条。
   - 修：跨泳道正交连接线；左侧调用深度缩进/父级轨道；默认选中失败节点；顶部失败横条（缺什么能力/时间）；失败条 ≥24px 命中 + 整行 4% 红底；检查器拒绝告警置顶。
2. **A baseline 的“启动团队”重复**（`keel-sec-09.png`）：右上按钮与检查卡内按钮状态不一致，2/3 未通过仍像是可启动。只保留一个权威控件，检查未过时两处同禁用同原因。（B 实现时同样只允许一个入口。）

## 3. P1（结构性，非抛光）

- **双 H1**：页边对象名 26px 与纸面节名 28px 同级；对象名必须是唯一 H1（30–32px，sticky），节名 18–20px。
- **权限表被拉成表单**：每行重复 9px“范围”标签、字段 48–51px、名称到控件 600px 空白、无列头；应做成表：能力/key/风险/范围四列，范围 32px 紧凑印章，表宽 760–820 或双列。
- **琥珀超载**：品牌、未保存、敏感、范围提升、待办、当前字段都用琥珀；应只保留“未保存/待办”，风险用独立黄→红刻度，品牌强调退回白/中性。
- **主操作不随状态走**：脏状态时“试跑”是实心主按钮，“保存 3 项”只是描边；脏状态应让保存做主，试跑降次级。
- **字号/对比度地板缺失**：中文 9–10px、mono key 9px、次要文字约 3.5–4.5:1；正文 13–14、元数据 12、mono key 11、对象标题 30–32、节标题 18–20；非 disabled ≥4.5:1。
- **设置入口缺失**：B 页头只有待办/实时/搜索/头像，IA 承诺的齿轮/设置不可见；补齿轮或头像菜单明确“设置”。
- **记录/审计/变更记录三种词**：定一套：章节“记录”、节“变更记录”、能力“查看记录”；“审计”只做技术词。
- **移动端运行页**：失败卡无时间/chevron/查看原因；停止运行是实心红块（破坏性操作过强）；底部检查器 sheet 未画。
- **移动端身份页**：“本团队”没有“范围”标签；桌面/移动语义不一致。
- **工作区胶囊混义**：“可编辑/可查看”是权限，“团队”是来源，同一胶囊位；来源移副标题，右侧只留权限。
- **五态只覆盖账号列表**：权限矩阵、Bot、团队、运行、移动端没有页面级五态；加载/成功注释与画面对不上。
- **四档 viewport 只交两档**：只有 1240 桌面 + 390 移动；补 1024/768 关键页（身份矩阵 + 运行）。
- **身份章排 04 + drill-in**：高频账号管理路径变长；身份章索引直接落账号列表，桌面保留常驻 280px 索引列（B drill-in 的唯一例外），移动端提前或加账号快捷入口。
- **账号混表（A baseline）**：在线/12 分钟前/运行中/周一/已禁用同列；“2 个待处理”没有行级标记/筛选。拆类型/存在状态/运行状态三列，待处理可点筛选。
- **有效能力卡截断**：说“可用 8 · 被挡下 2”，只显示 5 行；显示 5/10 或展开。
- **方向对照不公平**：C 只有线框，D 像未完成表格；C 补 3 张成品或明确“特征探针不投票”，D 单独放 seed 区。

## 4. 五态与移动端

- 五态有设计但只覆盖账号列表；权限不足态最好（缺什么/找谁），但不是页面级。
- 移动端是真响应式（tab、权限组卡、纵向时间线），关键操作未被遮挡；缺失败诊断链、绝对时间、设置入口。
- Pad 只有一句话，没有 1024/768 实拍。

## 5. 五条最高优先级修改

1. 运行页画成真正的“时间账”：调用边、失败默认焦点、失败横条、30s 网格、≥11px 轴、24px 命中。
2. 建立字号/对比度地板，砍掉 9px 中文；用减少文案而不是缩小字号保密度。
3. 权限表做成表（四列/32px 范围印章/单列头/最大宽或双列），琥珀只表示未保存/待办。
4. 一屏一个主操作，随状态变化：脏→保存主，试跑次；移动端停止描边+确认；启动团队去重。
5. 补页面级五态、1024/768、移动端检查器 sheet、设置齿轮、记录/审计用词统一。

- **必须先修：** P0 运行页 + P1 双 H1/字号地板/保存主次/琥珀语义/设置入口/用词。
- **兜底：** 若运行页仍画不出调用边与失败焦点，用 A 的 DAG 做运行默认视图，B 时间线做第二视图。

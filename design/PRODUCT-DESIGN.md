## 0. 一页结论

1. **产品定位**：Keel 是一台部署里的「AI 员工操作系统」。人给能力，Bot 干活，团队有使命，所有动作可追溯。
2. **信息架构（推荐方向 B · 账簿）**：五章 —— 工作区（会话 + 待我处理）、员工（Bot）、团队（TeamBot + 运行）、身份（账号 / 权限组）、记录（审计）；部署配置在右上角设置。顶部章节索引带 + 页边 + 纸面带；对象各有唯一真源，跨章只做「索引视图 + 回到真源」。
3. **权限的产品语言**：界面只说「能力」与「范围」，不暴露 permission-key；所有条件渲染走 `can(key, resource)`，后端权威；没有权限就 403 并说清缺什么、找谁。
4. **最重要的三块新界面**：权限组的能力带 + 范围印章 + 签记条；Bot 的「账号上限 ∩ 工作范围 = 有效能力」并排解释；TeamRun 的泳道 DAG（时间 × 执行者）+「图」切换。
5. **验收口径**：每页有目的陈述与唯一主操作；五态齐全；375/390/768/1440 可用；文案是人话；视觉只用既有令牌与 shadcn 官方件。

## 1. 产品定位与目标用户

### 1.1 一句话定位

> **Keel 让一台部署拥有自己的 AI 员工团队：谁在干活、能干什么、花了多少、出了事找谁，一眼可查。**

产品不是「聊天框 + 设置页」，而是三层结构：

```
部署（Deployment）
└── 账号（Account：人 / Bot / 服务）—— 权限主体
    └── Bot（AI 员工）—— Profile（账号 + 人设）+ 模型类型 + 默认模型 + 工作范围
        └── 会话（Session）—— 归属 Bot，默认只对所属账号可见
团队（TeamBot）—— 一句使命 + 一份 Bot 名单；不是权限主体，不拥有会话
团队运行（TeamRun）—— 账本投影：Mission 节点 + Bot/Session 节点 + 调用边
```

### 1.2 设计原则

| # | 原则 | 落到界面上的判据 |
|---|---|---|
| P1 | **能力先于身份** | 任何按钮/导航的出现条件是 `can(key, resource)`，不是「是不是管理员」。身份只用于标签（人 / Bot / 超管徽章），不用于授权分支。 |
| P2 | **一个概念一个真源** | 账号只在「身份→账号」改；权限只在「身份→权限组」改；Bot 只在「员工→Bot」改；团队只在「团队」改；会话只在「工作区」读。其他页面只做只读索引与跳转。 |
| P3 | **旅程优先于页面** | 每页开头一句「这里能做什么」，结尾给下一步；创建流程结束必须落到「试跑 / 启动 / 查看运行」，不是回到空列表。 |
| P4 | **状态始终可见** | 加载、空、错、权限不足、成功五态都有设计；运行中/已归档/已禁用/已撤销在列表和详情同时可见；变化 2 秒内到达。 |
| P5 | **克制即专业** | 沿用既有 Keel 深色令牌、1px 描边、14px 正文、单一白色主操作；不用渐变、发光、彩色图标、装饰性动效。身份与权限是高后果界面，视觉不抢戏。 |

### 1.3 角色与 Job-to-be-done

| 角色 | 在这台部署里的位置 | 核心 JTBD | 成功的样子 | 失败的样子（要防的） |
|---|---|---|---|---|
| **部署 Owner / 超级管理员** | 部署级，唯一不可删除、不可禁用；可跨租户；全部操作审计 | 「把一台裸部署变成可控的 AI 团队，并且随时能收回。」 | 初始化 10 分钟内完成；能说清每个人/每个 Bot 能干什么；出事能查到人 | 忘记密码锁死；超管权限被 Bot 借走；审计里只有 id 没有人话 |
| **团队管理员** | 租户内；有账号、权限组、Bot、团队的管理能力，但不得超过自己 | 「给人刚好够用的能力，给 Bot 刚好够用的工具。」 | 建组、拉人、配 Bot、启动团队一条线走完；越权时看到「你最多只能授予…」 | 只会逐个账号点权限；授多了收不回；跨账号 Bot 不知道怎么才能用 |
| **普通成员** | 租户内；只看到自己该看的会话与被授予的 Bot | 「找到能帮我干活的 Bot，交代任务，看到结果和它用了什么。」 | 工作区里能搜到可用的 Bot；共享会话有明确来源与权限；被撤销时被告知原因 | 满屏是别人的会话；点开就 403 白屏；不知道找谁开权限 |
| **Bot（AI 员工）** | 账号主体，无浏览器会话；用绑定 Bot 的 API key 行动 | 「在授权范围内完成被交代的任务；越权时得到明确拒绝。」 | 工具调用被拒时返回「缺哪个能力、找谁」；每次调用有审计 | 静默失败；用调用者的权限；TeamBot 给它额外授权 |
| **管家 Bot** | 高权限 Bot（不是超管）；典型首启员工 | 「听懂一句话需求，组建团队、配权限、跑起来，并让人看懂它做了什么。」 | 一句话后产出成员 Bot、团队、权限组、运行链接；越权步骤明确求助 | 需要人类专属旁路；偷偷提权；做完只留一堆工具日志 |

### 1.4 权限模型的产品化解释（界面必须教会用户的三件事）

**第一件：账号是权限主体，Bot 是执行者。**

```
账号 A（人）──拥有──> Bot X ──执行时有效权限 = A 的权限 ∩ X 的工作范围
账号 B（Bot）─拥有──> Bot Y ──同上；人/Bot 账号规则完全对称，只有登录方式不同
```

**第二件：团队不是权限主体。**

TeamBot 只是一句 Mission + 一份 Roster。它不拥有会话，不向成员授予任何权限。成员 Bot 各自按自己的账号与工作范围执行。界面上任何「给团队授权」的入口都不存在——这是刻意的，不是缺失。

**第三件：调用 Bot 是能力授权，不是权限合并。**

调用者持有 `bot.invoke` 就能用这个 Bot；Bot 以自己的权限执行，结果返回调用者。界面必须把这件事说透，否则用户会以为「我调用了高权限 Bot，我就有了它的权限」。

三个常见误解与界面反制：

| 误解 | 界面反制 |
|---|---|
| 「我是管理员，所以我配的 Bot 也能管一切」 | Bot 详情「有效权限」页明确写：账号是上限，工作范围是收窄；逐项列出「被工作范围挡掉」的能力。 |
| 「把 Bot 放进团队，团队就有它的权限」 | 团队编辑器顶部常驻说明；roster 行只显示「可调用 / 不可调用」，不显示「已授权」。 |
| 「Role/人设写了就能做」 | 人设编辑器下方常驻一句：「人设决定语气与做法，不授予任何能力。」 |

## 2. 信息架构

### 2.1 对象清单与真源

| 对象 | 用户语言 | 唯一真源页 | 其他出现方式 |
|---|---|---|---|
| Account | 账号 | 身份 → 账号 → 账号详情 | Bot 详情的「所属账号」只读链接；记录里的操作者链接 |
| PermissionGroup | 权限组 | 身份 → 权限组 → 组详情 | 账号详情的「所属组」只读；Bot 详情的能力来源说明 |
| PermissionGrant | 能力（key + 范围） | 权限组详情 → 权限 | 账号详情「有效权限」只读汇总 |
| Bot | Bot / AI 员工 | 员工 → Bot 详情 | 工作区会话头、团队 roster、DAG 节点、记录对象；均为只读引用 |
| BotKey | Bot 密钥 | 员工 → Bot 详情 → 密钥 | 无 |
| TeamBot | 团队 | 团队 → 团队详情 | Bot 详情「所属团队」只读；工作区 Mission 条 |
| TeamRun | 团队运行 | 团队 → 团队详情 → 运行 → 某次运行 | 会话/记录里的「查看运行」链接 |
| Session | 会话 | 工作区 → 会话 | Bot/账号详情的「最近会话」是可筛选索引，点击回到工作区 |
| AuditEvent | 审计记录 | 记录 | 详情抽屉；不嵌入其他页面 |
| DeploymentConfig | 部署设置 | 设置（模型接入 / 密钥 / 插件 / 技能 / 外观…） | 关于页只读摘要；Bot 编辑器的「管理模型接入」是带权限的跳转 |

### 2.2 导航壳（推荐方向 B · 账簿）

> 方向探索与取舍见 `design/DIRECTIONS.md`。A 控制台（左栏 + 列表/详情 + 页签）保留为 baseline，不再作为推荐结构。

```
┌──────────────────────────────────────────────────────────────────────┐
│ K Keel   acme·生产   01 工作区  02 员工  03 团队  04 身份  05 记录      │ 56
│                                            待办 3  ● 实时  ⌕  李      │
├──────────────┬───────────────────────────────────────────────────────┤
│ 身份/权限组   │ 04 / 02 能力                    7 项已授 · 3 未保存  │
│ 客服组        │ ───────────────────────────────────────────────────── │
│ 自定义·8 人   │ 01 会话                           已授 3 / 4          │
│ 成员 8        │ 查看会话   session.read   常规    [范围 本团队 ▾]     │
│ 能力 7        │ 继续会话   session.write  常规    [范围 本团队 ▾]     │
│ 最近修改 14:12│ 删除会话   session.delete 敏感    [范围 未授予 ▾]     │
│               │ ───────────────────────────────────────────────────── │
│ [切换权限组]  │ 02 Bot                            已授 2 / 5          │
│               │ 查看 Bot   bot.read       常规    [范围 整个租户 ▾]   │
│ 01 概览       │ 调用 Bot   bot.invoke     高危    [范围 本团队 ▾]     │
│ 02 能力  ←    │ ───────────────────────────────────────────────────── │
│ 03 成员       │ 本次变更 3 项 · 保存前可核对                          │
│ 04 变更记录   │ 签记：李娜 · 团队管理员        [保存并签记]          │
└──────────────┴───────────────────────────────────────────────────────┘
```

**三个部分**：

| 部分 | 作用 | 规则 |
|---|---|---|
| **章节索引带**（56px） | 一级导航：01 工作区 / 02 员工 / 03 团队 / 04 身份 / 05 记录；右侧待办、实时、搜索、头像、设置 | 有权限才出现；无权限章节整章不渲染；不把低频项塞进「更多」 |
| **页边 spine**（226px） | 当前对象的身份、关键事实、主操作、章节内索引、切换与账本编号 | 滚动时固定；对象页的主操作在页边；章节内索引用编号 01–05，不用页签 |
| **纸面 sheet** | 当前章节的内容，按「带」组织：带号 + 标题 + 分隔线 + 行 | 不套卡片；行用 hairline 分隔；低频细节进带内折叠或页边索引 |

**章节 → 索引 → 对象页**（drill-in）：

1. 点章节名 → 该章的**对象索引**（一张账页：所有账号 / 权限组 / Bot / 团队 / 运行）。
2. 点索引行 → **对象页**（页边 + 纸面）。页边顶部有「切换」搜索（1 击 + 输入）与「全部 N」入口，补足 drill-in 的切换成本。
3. 对象的章节内索引（如 Bot 的 01 身份 / 02 工作方式 / 03 能力 / 04 密钥 / 05 会话）在页边；纸面只显示当前章节。
4. 运行是团队对象页的一节，也是一张可分享的独立页（`/teams/:id/runs/:runId`）；它不拥有自己的导航章节。

| 章节 | 图标（lucide 语义） | 可见条件 | 索引 | 对象页主操作 |
|---|---|---|---|---|
| 01 工作区 | `message-square` | 始终 | 会话（我的 / 共享给我 / 团队）+ 待我处理 | 新建会话 |
| 02 员工 | `bot` | `bot.read`（任一范围） | Bot 索引 | 试跑 |
| 03 团队 | `users` | `team_bot.read` 或任一可见运行 | 团队索引 + 最近运行 | 启动 / 停止 |
| 04 身份 | `shield` | `account.read` ∨ `permission.read` | 账号索引（默认，280 常驻）/ 权限组索引 | 加入权限组 / 保存并签记 |
| 05 记录 | `activity` | `audit.read` | 账本（筛选 + 表格） | 导出 |
| 设置 | `settings` | 部署配置可见 | 模型接入 / 密钥 / 插件 / 技能 / 外观 / 关于 / 本机与认证 | 按节 |

**身份章的唯一例外（视觉评审后定）**：身份是最高频路径，桌面不采用 drill-in，而是**常驻 280px 索引列**（账号默认 / 权限组是同一索引的第二个子页），点行直接在右侧纸面展开；页头不重复对象名。移动端用「账号 / 权限组」segmented 提前账号入口。其余章节仍是「章节 → 索引 → 对象页」。

**「待我处理」**：跨对象的一条窄带，放在工作区顶部与相关索引页；聚合越权调用、失败运行、缺 `bot.invoke` 的成员、待批准的授权。每条给「谁 / 什么 / 为什么 / 一个动作」，点击回到对应对象页；它不是新章节，也不是第二套审计。

**为什么不是左栏 + 列表/详情**：

- 旧设置页的左栏 + 卡片堆叠是「配置中心」的惯性；身份与访问的核心心智是**记录**（谁被授予了什么、谁做了什么），账簿结构比卡片更贴语义。
- 权限矩阵、审计、运行都是长表；纸面带 + hairline + 印章比卡片套卡片更能比较，也更安静。
- 页边在滚动时始终可见，替代面包屑与页签；「签记」把高后果保存变成一次可理解的承诺。

**三尺寸**：桌面 = 章节带 + 页边 + 纸面（身份例外：章节带 + 280 索引列 + 纸面）；Pad = 页边折叠为纸面上方的对象摘要带，章节带横向可滚；移动 = 章节选择器 + 摘要卡 + 单列纸面（见 §8）。

### 2.3 二级页面树

```
工作区（章节 01）
├── 会话（默认：我的）
│   ├── 筛选：我的 / 共享给我 / 团队会话
│   └── 会话页（对话 + 右侧事实面板）
├── 待我处理（越权调用 / 失败运行 / 缺 invoke 的成员 / 待批准的授权）
└── 新建会话（选择可调用的 Bot）

员工（章节 02）
├── Bot 索引（一张账页：搜索 / 归属账号 / 状态 / 模型类型）
├── 新建 Bot（3 步：身份 → 工作方式 → 能力）
└── Bot 页（页边索引）
    ├── 01 身份（归属、人设、一句话用途）
    ├── 02 工作方式（模型类型、默认模型、工作说明）
    ├── 03 能力（账号上限 ∩ 工作范围 → 有效能力）
    ├── 04 密钥（签发 / 吊销 / 最近使用）
    ├── 05 会话（最近索引，跳工作区）
    └── 试跑（Sheet / 全屏：真实一轮 + 能力解释）

团队（章节 03）
```

## 3. 关键旅程

### J1 首次部署：bootstrap → 超管 → 权限组 → 账号

**触发**：`keel serve` 启动，库中无超管，用户打开浏览器。

| 步 | 用户看到 | 用户做 | 系统反馈 | 失败与恢复 |
|---|---|---|---|---|
| 1 | 全屏「这台部署还没有管理员」；终端命令块 `keel admin bootstrap` + 复制 | 在终端执行 | 页面轮询/SSE 感知到 token 已生成，启用口令输入 | 命令不存在/无权限：显示「在这台机器的项目目录里运行；容器部署请看部署文档」 |
| 2 | 一次性口令输入 + 「继续」 | 粘贴 token | 校验通过 → 进入创建管理员 | token 过期/复用：「这个口令已失效，回终端重新生成一个。」 |
| 3 | 用户名、显示名、临时密码 | 填写 | 创建成功 → 自动登录 → **强制改密**页 | 用户名占用：「这个用户名已有人用，换一个。」 |
| 4 | 「先换成只有你知道的密码」 | 设新密码 | 进入产品；顶部出现 4 步设置清单 | 密码太弱：逐条规则实时显示，不提交才报错 |
| 5 | 设置清单：① 建权限组 ② 建账号 ③ 创建管家 Bot（默认勾选）④ 试跑 | 按顺序或跳过 | 每完成一项打勾；全部完成清单消失 | 跳过：清单保留在「身份」索引页，不阻塞使用 |
| 6 | 预置结果：管家 Bot + `管家` 权限组 + 一个 Bot 账号 | 直接去工作区说话 | 管家 Bot 出现在员工列表；工作区可新建与它的会话 | 预置失败：清单显示「管家没建成」，给重试与手动创建 |

**关键规则**：管家 Bot 属于独立的 Bot 账号，**不属于超管账号**——超管权限不得委托给 Bot。`管家` 组只含 `bot.manage`、`team_bot.manage`、`permission.manage`、`account.read`、`bot.invoke` 等必要能力，范围限于本租户。

**退出**：进入工作区；清单可在「身份」索引页继续。

### J2 管理员创建 Bot 并试跑

**触发**：员工 → 新建 Bot（或空态「创建第一个 Bot」）。

| 步 | 界面 | 说明 |
|---|---|---|
| 1 | 3 步对话框：身份 | 名字、所属账号（默认我的账号）、人设（可选，默认「通用助手」）、一句话用途 |
| 2 | 工作方式 | 模型类型（文本/图像/决策/实时…）、默认模型（从部署已接入目录选）；显示「运行时可由调用参数覆盖」 |
| 3 | 能力 | 工具白名单（按族分组，每项显示所需能力与可用性）；能力上限默认继承账号，可逐项收窄 |
| 4 | 创建 | 主按钮「创建 Bot」；次按钮「创建并试跑」 |
| 5 | 成功 | 落到 Bot 详情；顶部成功条：「客服一号已创建。下一步：试跑一轮，确认它能做什么。」 |
| 6 | 试跑 | 右侧 Sheet：输入一句任务 → 流式回答 + 工具调用卡；底部「本轮用了 3 个工具 · 2 项能力」；越权时显示「被工作范围挡下：读取密钥」 |

**失败与恢复**：
- 默认模型不可用 → 模型选择器内联「这个模型当前不可用，换一个或去设置检查接入」；
- 工具未安装 → 该行禁用并写「部署未安装」；
- 账号选择越权 → 账号选择器只列可见账号；「放到其他账号」需要 `account.manage`，否则禁用并解释；
- 创建被拒（`grant ⊆ own`）→ 保留所有输入，错误条写「你不能把 Bot 放到这个账号：你对该账号没有管理能力」。

**退出**：Bot 详情；或直接试跑。

### J3 建 TeamBot → 启动 → 看 DAG

**触发**：团队 → 新建团队。

| 步 | 界面 | 说明 |
|---|---|---|
| 1 | 基本信息 | 团队名、Mission（大文本，必填）；右侧示例与「使命会进入每个成员的会话」说明 |
| 2 | 成员 | 队长位固定第一行；「添加成员」打开搜索选择器；每个候选显示归属账号与可调用性 |
| 3 | 启动前检查 | 三行检查：Mission 非空 / 已选队长 / 所有成员可调用；每行可「去处理」 |
| 4 | 启动 | 主按钮「启动团队」；确认对话框说明：队长会创建/调用成员会话、会产生用量、可在运行页停止 |
| 5 | 运行 | 跳到运行详情：Mission 节点先出现，成员节点随事件到达；顶部「实时」指示 |
| 6 | 结束 | 运行状态变为完成/失败/已停止；右侧汇总时长、用量、失败节点；「回到团队」与「再跑一次」 |

**失败与恢复**：
- 无 `bot.invoke` 的成员 → 不能加入；行内「需要它的归属者授予你『调用 Bot』能力」+「复制申请」；
- 启动时队长被撤权 → 403 对话框：「队长 Bot 的调用权已被撤销。换一个队长，或请归属者恢复授权。」
- 运行中成员被撤权 → 该成员下一次调用 403，节点标记「已失去调用权」，不影响其他成员；
- 运行中刷新/断线 → 断线横幅 + 自动重连；已加载节点不丢。

**退出**：团队详情「运行」列表，或工作区。

### J4 管家 Bot 一句话建团队并配权限

**触发**：工作区 → 与管家 Bot 的会话 → 用户输入「帮我组建一个客服团队，能查订单、能升级给人工，跑起来看看」。

| 步 | 界面 | 说明 |
|---|---|---|
| 1 | 用户消息 | 普通用户气泡 |
| 2 | 管家回应（计划） | 一条「我准备这样做」卡：建 3 个成员 Bot、建 1 个团队、建 1 个权限组、启动。可展开细节 |
| 3 | 工具调用流 | 每个动作一张工具卡：「创建 Bot 客服一号」→ 成功/失败；「创建团队」→ 成功；「配置权限组」→ 成功；「启动团队」→ 运行链接 |
| 4 | 越权时 | 工具卡变「需要你决定」：缺 `secret.read`，说明「这一步需要读取密钥，但管家没有这个能力。找一个有该能力的人来批准。」；若当前用户也没有，显示「请找 王强（部署管理员）」 |
| 5 | 完成 | 一条总结卡：团队名、成员、权限组、运行状态、用量；「查看运行」「查看团队」两个链接 |
| 6 | 追溯 | 总结卡底部「这次共 14 步，全部可在记录中查看」；点开跳到记录筛选（actor=管家 Bot） |

**关键规则**：管家没有专属代码路径；它做的每一步都是普通人能做的同一个 API。界面不显示「Bot 专用」任何东西，只显示「谁做的、做了什么、结果如何」。

**失败与恢复**：
- 管家缺 `permission.manage` → 不能建组；它会停下来求助，而不是绕过；
- 成员 Bot 创建成功但启动失败 → 总结卡显示部分成功，列出「已创建 / 未启动」，给「重试启动」；
- 用户中途改需求 → 管家在下一轮计划里说明「将复用已建的两个 Bot」，不重复创建。

**退出**：团队运行页；或继续对话调整。

### J5 普通成员被分享一个会话 → 查看/编辑 → 被撤销

**触发**：账号 A 在工作区打开自己的会话 → 右上角「共享」→ 选择账号 B，关系「可编辑」→ 保存。

| 步 | 账号 A 看到 | 账号 B 看到 |
|---|---|---|
| 1 | 共享对话框：搜索人/组、选「可查看/可编辑」、说明「对方会收到通知，可随时撤销」 | — |
| 2 | 会话头部出现「已共享给 1 人」徽章 | 工作区筛选「共享给我」出现该会话，带「来自 李娜 · 可编辑」 |
| 3 | — | 打开会话：顶部常驻横幅「由 李娜 共享 · 可编辑」；输入框可用 |
| 4 | 撤销：共享列表移除 B | 若正开着：2 秒内横幅变「共享已撤销 · 只读」，输入框禁用；下一次写入返回 403，页面切到「访问已撤销」 |
| 5 | — | 「访问已撤销」页：说明谁撤销的、你仍拥有什么（自己的工作区）、「返回工作区」 |

- B 无 `session.read` → 共享失败/对方看不到；A 的共享对话框提示「对方没有查看会话的能力，先给他加权限组」；
- 会话所属 Bot 归档 → 双方都看到「Bot 已归档，会话只读」；
- 撤销后 B 刷新页面 → 403 资源页（不泄露会话内容）。

**退出**：B 回到工作区；A 的共享状态更新。

### J6 Bot 密钥签发与吊销（支撑无人值守）

## 4. 页面规格

> **容器说明（方向 B）**：对象页的章节用**页边索引**（01 概览 / 02 能力 / 03 成员 / 04 变更记录…），不是页签；纸面只显示当前章节。下面每页的「信息层级」描述内容与顺序，「组件映射」写生产组件；A baseline 的页签形态保留在 OpenDesign 的 A 完成稿中，仅作对照。
>
> 每页固定六项：目的、主操作、信息层级、组件映射、五态、移动端。五态细节汇总在 §5。

### 4.1 登录 / 首次设置 / 强制改密

**目的**：让正确的人以最少的步骤进入，并让「这台部署还没有管理员」成为一条可执行的指引，而不是一个 503。

**主操作**：登录 →「登录」；首次设置 →「创建管理员」；强制改密 →「保存并进入」。

**信息层级**：
1. 品牌与一句用途（Keel · AI 员工工作台）；
2. 当前要做的一件事（登录 / 设置管理员 / 换密码）；
3. 表单与错误；
4. 次要帮助（忘记密码怎么办、本机模式说明、部署文档）。

**组件映射**：`Card`（max-w-sm 384）、`CardHeader`、`CardContent`、`Field`、`Input`、`Button`、`AlertDialog`（无）、`Notice` 形态的 `Card`（错误条）、`Spinner`、`Kbd`（CLI 命令）、`Separator`。

**五态**：
- 加载：按钮 loading + 禁用，文案「正在验证…」；页面不闪骨架（表单已在）。
- 空：不适用（表单本身是空态）。
- 错：字段级错误 + 保留输入；网络错误用错误条 + 「重试」。
- 权限不足：登录失败不区分账号/密码；限速显示「尝试次数过多，2 分钟后再试」；无超管时显示首次设置而不是登录。
- 成功：进入工作区；首次登录落到强制改密；顶部一次性欢迎条。

**移动端（375/390）**：卡片占满宽度减 32px；输入 44px 高；按钮全宽；CLI 命令块可横向滚动、带复制；键盘弹出时按钮不被遮挡（滚动容器）。

**特殊状态**：
- `local-only`：不出现登录页；右上角常驻「本机模式」小徽章；「我的账号」里说明「本机免登录，所有操作记为 local-admin」。
- 无超管：页面标题「这台部署还没有管理员」，步骤 1/2/3 横排（移动端竖排）；token 输入框旁有「口令在哪？」说明。
- 超管找回：登录页底部「超级管理员忘记密码？」→ 展开只读命令 `keel admin reset --username …`，写明「只能在这台机器的终端执行」。

### 4.2 身份 · 账号索引 / 账号页

**目的**：回答「这台部署里有谁、他们能做什么、现在是否可用」，并把「加人 / 停用 / 找权限」变成一步。

**主操作**：列表 →「新建账号」；详情 →「加入权限组」（次要「禁用账号」）。

**信息层级**：
1. **常驻索引列（280）**：顶部「账号 / 权限组」segmented（账号默认）+ 搜索 + 账号行（名字、用户名、权限组、存在状态）；页头主操作「新建账号」。身份章是 B drill-in 的唯一例外。
2. **纸面头部**：标题「账号」+「2 个待处理」筛选 + 主操作「新建账号」；一句目的 + 汇总（12 位 / 9 人 / 3 Bot）。
3. **账号表（五列）**：账号（名字 + 用户名）/ 类型（人 / Bot）/ 权限组 / 状态（在线 / 离线 / 已禁用）/ 最近活动。**「待处理」不再混进状态列**：它是行级徽章 + 顶部筛选，例如「已禁用 + 待处理」。
4. **账号页**：头部（头像、名字、用户名、类型/状态、所属租户）+ 章节：概览 / 能力 / Bot / 会话 / 安全；危险操作收进「更多」。
5. 排序默认按最近活动；搜索支持名字、用户名、权限组。

**组件映射**：`Table` + `Th/Td`、`Badge`、`Avatar`、`Input`（搜索）、`Select`（筛选）、`Button`、`Tabs`（A baseline）/ 常驻索引列 + `Button`（B）、`Card`（仅空态/浮层）、`Field`、`Dialog`（新建/重置）、`AlertDialog`（禁用）、`Empty`、`Skeleton`、`DropdownMenu`（行操作）、`Breadcrumb`。

**账号页的章节（B）**：
- **概览**：身份（类型、创建时间、最近登录）、权限组、拥有的 Bot（最多 3 个 + 查看全部）、最近会话（最多 5 条 + 查看全部）、状态说明（禁用时写「已禁用：会话已吊销，Bot 密钥不可用」）。
- **能力**：只读。上半「有效能力」按域分组，显示「能力名 + 范围 + 来源（哪个组）」；下半「所属权限组」列表 +「加入权限组」。**不提供直接授权编辑**（见 §2.6）。
- **Bot**：该账号拥有的 Bot 列表（名称、模型类型、状态、最近活动）；行点击进 Bot 详情。
- **会话**：最近会话（标题、Bot、时间、可见性）；点击回工作区。
- **安全**：当前会话（设备/时间/近似地点掩码）、最近失败登录、禁用后果说明、重置密码。
  - 人账号：重置密码 → 生成一次性临时密码，显示一次，说明「对方下次登录必须修改」。
  - Bot 账号：隐藏重置密码；显示「Bot 使用密钥登录」+ 管理的 Bot 密钥入口。
  - 超管：禁用/删除按钮禁用并写「超级管理员不可禁用或删除」；重置密码禁用并写「只能在这台机器的终端重置」。

**空态**：还没有账号 → 「先建一个账号，再决定他能看到什么。」+「新建账号」+「先建权限组」。
**权限不足**：无 `account.read` → 身份章节不出现；直接访问 → 403 页。
**移动端**：索引列变成账号列表页；顶部 segmented「账号 / 权限组」提前账号入口；表格变卡片（名字+用户名 / 权限组 / 状态 + 最近活动）；行点击整卡；新建用底部固定按钮；不做 5 个横向 tab。

### 4.3 身份 · 权限组索引 / 权限组页

**目的**：让「谁能做什么」变成可比较、可维护的一张表，而不是散落在各账号里的开关。

**主操作**：组详情 →「保存并签记」；列表 →「新建权限组」。

**信息层级**：
1. **常驻索引列（280）**：内置组与自定义组；每行「名称 + 说明 + 成员数 + 能力数 + 内置徽章」；顶部 segmented「账号 / 权限组」（权限组选中）；底部「新建权限组」。
2. **纸面头部**：标题「客服组」（唯一 H1，30–32）+ 自定义/成员徽章 + 一句说明 + 汇总（8 位 / 7 项 / 3 项未保存 / 最近修改）+ 次要「另存为副本」。
3. **能力表（四列，宽 820）**：能力名 / 风险 / KEY / 范围；**只有一个「范围」列头**；范围是 32px 紧凑印章（未授予用虚线），不再每行重复「范围」标签；风险徽章紧跟能力名，使用独立的黄→红刻度（常规/敏感/高危），不占用琥珀。
4. **本次变更**：3 行「旧值 → 新值」，保存前可核对；影响人数与生效时机写在下面。
5. **签记条**：变更数 +「放弃」+「保存并签记」（脏状态为唯一实心主按钮）。

**组件映射**：`Card`（空态/浮层）、`Tabs`（A baseline）/ 常驻索引列 + `Button`（B）、`Input`（搜索）、`Accordion`/`Collapsible`（域分组）、`Table`（四列能力表）、`Select`（32px 范围印章）、`Badge`（风险/内置）、`Button`、`Dialog`（新建组/加成员）、`Command`/`Combobox`（成员搜索）、`AlertDialog`（移除成员/删除组）、`Empty`、`Skeleton`、`Separator`。

**权限矩阵规则**：
- 行 = 一个 key；四列 = 能力名、风险徽章、KEY（mono 11）、范围印章；表宽 820，不做 600px 的名称到控件空白；
- 范围选项：`未授予 / 仅自己 / 本团队 / 整个租户 / 全部`；`全部` 仅超管可选，其他人在下拉中看到但禁用，附「只有部署管理员能授予跨租户范围」；
- 琥珀只用于未保存/待办；风险用独立的黄→红刻度（常规中性、敏感黄、高危红），不把风险染成琥珀；范围提升/新增用中性或信息蓝，不占琥珀；
- 授予者自己的上限：超过自己持有范围的行整行禁用，行尾写「你最多能授予『本团队』」；
- 域头：域图标 + 域名称 + 「已授 3/6」+ 展开/折叠；搜索时自动展开命中域，命中词高亮；
- 内置组：`super-admin` 只读并说明「超级管理员固定拥有全部能力」；其他内置组可复制为自定义组（「另存为副本」），不直接改；
- 风险：`高危` 徽章用于 `bot.invoke`、`secret.read.value`、`account.credential.reset`、`plugin.lifecycle.*` 等；行内一句「授予后对方能读取密钥值」；
- 保存：只提交变更 diff；冲突（他人已改）显示「这个组刚被 王强 修改过，刷新后重试」，不覆盖。

**成员章节**：搜索 + 添加；每行「头像 + 名字 + 类型 + 已属组数 + 加入时间 + 移除」；添加时显示候选人的现有组，避免重复；移除前说明「移除后对方仍保留其他组与直接授权带来的能力」。

**空态**：还没有自定义组 → 「内置组已经覆盖常见岗位；如果团队有自己的分工，建一个自定义组。」+「新建权限组」+ 三个模板（客服 / 研发 / 只读）。
**权限不足**：无 `permission.read` → 身份章节不出现；无 `permission.manage` → 能力带只读，顶部条「你可以查看，但不能修改」。
**移动端**：索引列变组列表页；能力表每域一个 `Collapsible`，行内能力名 + 「范围 · 本团队」印章（`Select` 打开底部 Sheet）；签记条固定在底部导航上方。

### 4.4 员工 · Bot 索引 / Bot 页

**目的**：回答「我的 AI 员工有哪些、各自能干什么、现在能不能用」，并让创建/调整/试跑形成闭环。

**主操作**：列表 →「新建 Bot」；详情 → 干净状态以「试跑」为主，脏状态以「保存」为唯一实心主按钮、「试跑」降为描边；一屏一个实心主按钮。

**信息层级**：
1. 列表：搜索 + 归属账号/模型类型/状态筛选；卡片或紧凑表格，每行「名字 + 一句话用途 + 归属账号 + 模型 + 工具数 + 状态 + 最近活动」；
2. 详情页边：对象名唯一 H1（30–32px，sticky）+ 状态徽章 + 归属账号/人设/模型类型 + 章节索引 + 主操作；更多「复制 / 归档 / 删除」；
3. 页边索引：身份 / 工作方式 / 能力 / 密钥 / 会话；
4. 行为页：工作说明、模型类型、默认模型、工具；
5. 权限页：账号上限 → 工作范围 → 有效能力（三段式）。

**组件映射**：`Card`、`Table`、`Badge`、`Avatar`、`Button`、`Tabs`（A baseline）/ 页边 `Button`（B）、`Field`、`Input`、`Textarea`、`Select`、`Combobox`（模型）、`Checkbox`/`Switch`（工具开关，按工具族分组）、`Accordion`、`Sheet`（试跑）、`Dialog`（新建 3 步）、`AlertDialog`（归档/删除）、`Empty`、`Skeleton`、`DropdownMenu`、`Tooltip`（禁用原因）。

**新建 3 步（Dialog，移动端全屏 Sheet）**：
1. **身份**：名字（必填）、所属账号（默认「我的账号」；「放到其他账号」需 `account.manage`）、人设（可选，默认「通用助手」）、一句话用途（会显示在列表里）。
2. **工作方式**：模型类型（必选；选项旁一句「决定它能处理文字/图像/实时语音…」）、默认模型（Combobox，按 provider 分组；只列已接入且可用的模型）。
3. **能力**：工具（按族：文件、终端、网络、任务、MCP…；每项一句说明 + 所需能力 + 可用性）、能力上限（默认「继承账号」，可展开逐项收窄）。
- 右侧（桌面）固定「摘要」：名字、账号、人设、模型、工具数、能力数；底部「创建 Bot」/「创建并试跑」。

**行为页细节**：
- 工作说明：`Textarea`，6 行，提示「写它怎么做事、语气、边界；不授予任何能力」；下方计数与「查看示例」。
- 模型类型：`Select`；改变时提示「模型类型会影响可用工具与参数；已保存的默认模型可能需要重选」。
- 默认模型：`Combobox`；副文案「运行时可以由调用参数覆盖；每次会话会记录实际使用的模型」；右侧「管理模型接入」链接（需 `model.configure`）。
- 工具：按族折叠；每行「工具名 + 一句用途 + 所需能力徽章 + 开关」；不可用工具禁用并写原因（部署未安装/需要更高范围）；顶部「已选 6 / 可用 14」。

**权限页（产品差异点）**：
- 三列/三段：**账号上限**（来自所属账号的并集，只读）、**工作范围**（本 Bot 的 Harness permissions，可收窄）、**有效能力**（交集，只读，实时计算预览）。
- 有效能力按域分组；每项显示「可做 / 被工作范围挡下 / 账号没有」三种状态；**计数与行数一致**：说「可用 8 · 被挡下 2」就显示 10 行，或显示 5/10 +「展开全部」，不允许数字与可见行对不上；
- 顶部一句「Bot 只能做账号能做、且工作范围允许的事。人设不产生能力。」
- 「为什么它不能读密钥？」搜索框：输入能力名，直接定位该行并解释是哪一层挡下。

**概览页**：一句话用途、能力摘要（工具 N、能力 M）、最近 5 次会话（状态/时长/用量）、归属关系（账号、所属团队）、「试跑」引导卡。
**密钥页**：见 J6。
**会话页**：最近会话列表，点击回工作区；顶部说明「会话的真源在工作区，这里是最近索引」。

**空态**：还没有 Bot → 「先建一个 Bot：给它一个身份、一个默认模型和一组工具。」+「创建第一个 Bot」+「从管家模板开始」。
**权限不足**：无 `bot.read` → 员工入口不出现；只有 `bot.read` 无 `bot.manage` → 详情只读，保存按钮禁用并解释；无 `bot.invoke` → 试跑按钮禁用「你需要这个 Bot 的调用权」。
**移动端**：列表变卡片；页边变摘要卡（对象名 + 3 个事实 + 主操作/保存）；章节索引变顶部 `Select`；3 步创建变全屏 Sheet，步骤指示在顶部；工具列表单列；能力三段变纵向 accordion；脏状态保存固定在底部、试跑次之。

### 4.5 团队 · 团队索引 / 团队页

**目的**：把「一句使命 + 一份名单」变成可启动、可检查、可追溯的团队，同时让「团队不授权」这件事在界面上成立。

**主操作**：编辑器 →「启动团队」；列表 →「新建团队」。

**信息层级**：
1. 列表：搜索 + 状态筛选；每行「团队名 + Mission 一句 + 队长 + 成员数 + 最近运行状态/时间」；
2. 详情头部：团队名、状态（草稿/可启动/运行中/已停止）、主操作「启动团队」、更多「复制 / 删除」；
3. 页边索引：使命 / 成员 / 运行 / 记录；
4. 成员页：常驻说明条 + 队长行 + 成员列表 + 启动前检查；
5. 概览页：Mission 全文、队长、成员头像、最近运行、用量汇总。

**组件映射**：`Card`、`Table`、`Badge`、`Avatar`、`Button`、`Tabs`（A baseline）/ 页边 `Button`（B）、`Textarea`（Mission）、`Field`、`Command`/`Combobox`（添加成员）、`Select`（队长/角色）、`AlertDialog`（启动确认/删除）、`Sheet`（成员选择移动端）、`Empty`、`Skeleton`、`Separator`。

**常驻说明条（关键）**：
> 团队本身不拥有权限，也不拥有会话。每个成员 Bot 按自己的账号与工作范围执行；能不能调用某个 Bot，取决于你是否持有它的「调用 Bot」能力。

**Mission 编辑**：
- 大文本域（8 行），必填；占位示例：「在 24 小时内解决客户问题；无法解决时升级给人工，并附上订单号与已尝试的步骤。」
- 副文案：「每次成员会话都会带上这句使命。写清楚目标、边界、升级条件。」
- 保存后显示「已保存 · 影响下一次运行，不影响正在运行的会话」。

**Roster**：
- 队长行固定在顶部，带「队长」徽章；「更换队长」打开对话框，列出成员，说明「队长负责拆分任务、调用成员；它仍以自己的权限执行」。
- 成员行：头像、Bot 名、归属账号、模型类型、可调用性徽章（可调用 / 不可调用 / 已归档）、移除。
- 「添加成员」：搜索 + 筛选（本账号 / 其他账号 / 最近使用）；候选行显示归属账号与可调用性：
  - 可调用 → 「加入」；
  - 不可调用 → 「加入」禁用 + 行内「需要它的归属者授予你『调用 Bot』能力」+「复制申请」；
  - 已归档 → 禁用 + 「已归档，不能加入」。
- 跨账号不特殊：没有「跨账号团队」开关，只有可调用性。

**启动前检查（Preflight）**：
```
✓ 使命已填写
✓ 已选队长（客服一号）
! 2 个成员不可调用  [去处理]
```
- 主按钮在检查未全绿时禁用，旁边写原因；不是只灰掉。
- 全绿后「启动团队」→ 确认对话框：
  - 「队长 客服一号 会收到这句使命，并可以创建、分叉、调用成员会话。」
  - 「会产生模型用量；运行页可随时停止。」
  - 主按钮「启动」；次按钮「取消」。

**空态**：还没有团队 → 「给团队一句使命，再选几个 Bot 加入。团队本身不拥有权限。」+「新建团队」+「用管家 Bot 帮你建」。
**权限不足**：无 `team_bot.read` → 团队入口不出现；无 `team_bot.manage` → 只读，启动禁用；无队长 `bot.invoke` → 启动禁用并写「你对队长没有调用权」。
**移动端**：列表卡片；Mission 文本域全宽；Roster 单列卡片；启动按钮固定底部；添加成员用全屏 Sheet；检查项一行一个，状态图标 + 文案。

### 4.6 团队 · 运行页（泳道 DAG）

**目的**：回答「这次团队运行发生了什么、谁调用了谁、哪里失败、花了多少」，并让人能下钻到具体会话。

**主操作**：运行详情 →「停止运行」（运行中）或「再跑一次」（已结束）；节点 →「打开会话」。

**信息层级**：
1. 页边：团队名、运行编号、Mission 一句、队长/成员/用时/成本/发起人、主操作「停止运行」、章节索引「使命 / 成员 / 运行 / 记录」；
2. 纸面带头：运行状态、失败数、实时指示、「泳道 / 图」切换、导出；
3. **失败横条（全宽，红 4% 底）**：`1 个失败 · 14:35:18 · 调用「售后升级」被拒：缺「调用 Bot」能力 · 王强可授予` +「查看原因」；它在泳道上方，不在折叠里；
4. 主区默认**泳道**（时间 × 执行者）：左侧执行者列含**调用深度缩进与父级**（← 客服一号），条 = Session 时长/用量，**跨泳道正交调用边**从父条结束/调用时刻连到子条开始；失败条 ≥24px 命中 + 整行 4% 红底；
5. 右侧检查器（桌面 330px）：**默认选中失败节点**；拒绝告警置顶（时间 + 缺什么 + 找谁），其下才是会话、工具、权限判定、用量；
6. 纸面底部（可选）：队长小结（运行中「生成中」骨架；完成后一段人话总结）。

**组件映射**：`Breadcrumb`（页边顶部）、`Badge`、`Button`、`Card`（仅空态/错误）、`ScrollArea`、`Sheet`（移动端检查器 / 图）、`Tabs`（泳道/图切换）、`Separator`、`Skeleton`（待到达/小结生成中）、`Empty`（无运行）、`AlertDialog`（停止确认）、`Tooltip`（边/状态解释）。泳道是结构化数据的自绘投影；若用图表库，必须自绘皮肤，不继承默认 look。

**两种投影（同一账本，不产生第二真源）**：

- **Mission 是根节点**：泳道里渲染为全宽带，到队长的边是「下发使命」；「图」里渲染为顶部节点。它不是一个装饰标题。
- **泳道（默认）**：
  - 横轴时间（5 分钟跨度，30s 网格线，轴标签 ≥11px），纵轴执行者；队长在上，成员按首次调用时间排序；左侧执行者列显示**调用深度缩进 + 父级**（← 客服一号），不允许把父子误读成并行任务。
  - 条的长 = Session 时长，条内写 tokens/成本；同层不重叠；条高 ≥24px，失败条至少 24px 命中区。
  - **跨泳道正交调用边**：从父条结束/调用时刻出发，经左侧父级轨道或泳道间空隙，落到子条开始；`invoke` 实线、`create/fork` 虚线、被拒绝红色虚线 + 「调用被拒」；不画推断边。
  - 失败优先：默认选中失败节点；失败行整行 4% 红底；顶部失败横条写时间 + 缺什么 + 谁可授予；检查器把拒绝告警置顶。
  - 实时：条随事件延长/变色；2 秒内到达；顶部「实时 / 已断开，重连中」。
  - 空运行（刚启动）：Mission 带 + 「队长正在准备…」占位行；不是空白画布。
  - **兜底**：若某次运行的边无法稳定绘制，切到「图」默认；当前实现的跨泳道边已通过视觉评审，保持泳道默认。
- **图（切换）**：
  - 分层布局，不用力导向；Mission 在最上，队长在其下，成员按调用深度分列；同层按开始时间排序。
  - 边只画账本里真实存在的 `create / fork / invoke`；不推断、不补边。
  - 状态：`排队`（虚线框）、`运行中`（实线 + 计时）、`完成`（实心点）、`失败`（红色边 + 错误徽章）、`已停止`（灰色）、`失去调用权`（锁徽章）。
  - 选中节点高亮其入边/出边；其他节点降到 60% 不透明度；键盘可 Tab 到节点，Enter 打开检查器。

**检查器内容**：
- 摘要：Bot、所属账号、模型（实际解析出的）、开始/结束、时长、状态。
- 工具：按时间列出工具名、结果、耗时；失败的展开错误原文（人话 + 错误码）。
- 权限：本次运行允许/拒绝了哪些能力；拒绝项写「缺什么、找谁」。
- 用量：输入/输出 token、成本；子节点汇总到队长。
- 操作：「打开会话」→ 工作区；「查看记录」→ 05 章按该 Bot + 时间过滤。

**空态**：团队还没有运行 → 「这个团队还没有跑过。启动一次，运行记录会在这里展开成一条时间账。」+「启动团队」。
**权限不足**：无 `team_bot.read` → 团队章节不出现；有团队读但无会话关系 → 运行结构可见，节点检查器显示「你可以看到运行结构，但不能打开成员会话」；直接访问 → 403。
**移动端**：页边变摘要卡；泳道变纵向时间线（每个节点一张卡，左边连接线 + 边标签）；失败卡带时间 +「查看原因」chevron；点节点从底部弹出检查器 Sheet（拒绝告警置顶）；「图」进全屏 Sheet；「停止」改描边 + 二次确认，固定在底部。

### 4.7 记录（审计）

**目的**：回答「谁、对什么、做了什么、结果如何」，并支持按人和对象追一条链。

**主操作**：记录 →「导出」（有 `audit.read` 且允许导出）；行 → 打开详情抽屉。

**信息层级**：
1. 筛选条：时间范围（今天/7 天/30 天/自定义）、事件类型（登录/授权/调用/账号/团队/超管）、操作者、对象、结果；
2. 结果表：时间、事件（人话）、操作者、对象、结果、来源（IP 掩码）；
3. 详情抽屉：一句人话总结 + 结构化事实（谁、什么、何时、结果、请求编号）+ 相关链接（账号/Bot/团队/会话）；
4. 导出：CSV，按当前筛选；导出动作本身也进审计。

**组件映射**：`Input`/`Combobox`（筛选）、`Select`、`Table`、`Badge`（结果）、`Sheet`（详情）、`Button`、`Card`、`Empty`、`Skeleton`、`Pagination`（如无组件则用 `Button` 上一页/下一页 + 计数）。

**事件文案**（示例）：
- 「李娜 登录成功」/「王强 登录失败：密码不正确」
- 「李娜 把『查看会话』授予了 客服组（本团队）」
- 「管家 Bot 创建了 Bot『客服一号』」
- 「客服一号 调用了 Bot『订单查询』」
- 「超级管理员 张巍 读取了租户 acme 的审计记录」
- 「客服一号 的密钥『生产 Webhook』被吊销」

**空态**：还没有审计记录 → 「这台部署还没有产生需要记录的操作。」（新部署常见）
**权限不足**：无 `audit.read` → 记录章节不出现；直接访问 → 403，文案「需要『查看记录』能力」。
**移动端**：筛选收进「筛选」Sheet；表格变卡片（时间 + 事件 + 操作者/对象 + 结果）；详情全屏 Sheet。

### 4.8 403 / 404 / 断线 / 维护

**403（能力不足）**：
- 标题：「你没有查看这个页面的权限」
- 说明：「需要『查看账号』能力。找这台部署的管理员，把你的账号加入有该能力的权限组。」
- 动作：「返回工作区」+「复制申请说明」
- 附加：显示当前账号名与一个请求编号；不显示内部 key（除非展开「技术详情」）。

**404 / 无权访问（资源级）**：
- 标题：「找不到这个页面，或者你没有访问权限」
- 说明：不泄露资源是否存在；给「返回工作区」。
- 用于跨租户、私有会话、被撤销的共享。

**断线**：顶部横幅「连接已断开，正在重连…」；已加载内容保留；恢复后「已恢复」2 秒后消失。
**维护/启动失败**：全屏说明 + 命令 + 日志编号；不是白屏。

## 6. 权限感知 UI

### 6.1 三种结果，不许有第四种

| 结果 | 何时用 | 表现 | 反例 |
|---|---|---|---|
| **隐藏** | 这个动作对当前用户没有任何完成路径，且对象本身也不需要展示 | 导航项、章节、整块区域不渲染 | 把「新建 Bot」灰掉但不解释 |
| **禁用 + 原因** | 对象可见、动作有意义，但被更窄的条件挡住（最后一个超管、内置组、缺 invoke、范围不够） | 控件 disabled + 行内一句原因 + 可选「怎么获得」 | 只给 tooltip；键盘/触屏用户看不到 |
| **允许** | `can(key, resource)` 为真 | 正常控件 | 前端自己推断 owner |

**没有「假装允许、点了再 403」**：能在渲染时判定的就判定；不能判定的（资源关系在服务端）由服务端下发每项的 `canEdit/canShare` 标志，前端不猜。

### 6.2 `can()` 的展示层契约

```
can(key, resource?) -> boolean           // 只用于渲染
canExplain(key, resource?) -> {          // 只用于解释，不参与渲染分支
  allowed: boolean,
  missingKey?: string,                   // 人话能力名
  requiredScope?: "own"|"team"|"tenant"|"all",
  reason?: "no-key"|"scope"|"relation"|"disabled"|"archived"|"builtin"|"last-super-admin"
}
```

- 前端能力集由服务端按当前账号派生（`GET /v1/auth/session` + `GET /v1/permissions`），不在客户端硬编码；
- 资源级动作由列表/详情响应携带 `canEdit`、`canShare`、`canInvoke` 等布尔值；前端不根据 `ownerId === me` 推断；
- 身份字段 `kind`（human/bot/service）只用于标签与文案；`is_super_admin` 只用于「部署管理员」徽章和不可变规则的说明，不用于授权分支；
- 401 → 清空能力集并回登录；403 → 不清空，展示拒绝原因；能力集变化（SSE）→ 2 秒内重渲染，已打开页面自动降级。

### 6.3 403 页面的四个部分

1. **发生了什么**：「你没有查看这个页面的权限。」
2. **缺什么**：「需要『查看账号』能力。」（展开「技术详情」才显示 `account.read`）
3. **找谁**：「找这台部署的管理员，把你的账号加入有该能力的权限组。」若知道具体人，写「找 王强（部署管理员）」。
4. **下一步**：「返回工作区」+「复制申请说明」（一段可直接粘贴给人的话，含页面、账号、所需能力）。

### 6.4 Bot 的「权限不足」不是页面，是工具结果

Bot 没有浏览器。它的拒绝体验发生在会话里：

- 工具卡显示「被拒绝：缺少『读取密钥』能力」；
- 展开显示：需要的范围、当前账号的上限、Bot 工作范围是否收窄、建议找谁；
- 同一轮里 Bot 可以改用其他工具，但不得静默重试同一被拒工具；
- 所有拒绝进审计（actor=Bot，target=工具/资源）。

### 6.5 权限变化的实时性

- 账号被禁用 / 权限组变更 / `bot.invoke` 撤销 / 会话共享撤销 → 服务端 SSE 推送；
- 已打开页面：2 秒内出现横幅并降级（只读/隐藏按钮）；正在进行的写操作返回 403 后展示结果；
- 列表页：受影响的行动态更新（例如「可调用」变「不可调用」），不要求手动刷新；
- 断线：保留最后状态 + 「正在重连」，不假装实时。

### 8.2 移动端关键规则

- **章节 5 项，不再多**：工作区 / 员工 / 团队 / 身份 / 记录；「设置」在页头齿轮与头像菜单双重入口，绝不隐藏。第 6 个目的地应拆产品，不挤 tab。

- **运行**：纵向时间线；每条边在左连接线上写「调用 / 创建 / 分叉」；失败卡带时间与「查看原因」chevron；点节点弹底部检查器 Sheet（拒绝告警置顶）；「停止」用描边 + 二次确认，不做实心大红块。需要拓扑时，「图」进全屏 Sheet（可横向滚动），不把桌面图硬塞进 390。
- **对话框**：桌面 `Dialog`；≤767 用 `Sheet` 全屏（从底部，可关闭，标题固定，底部主操作）。
- **触控目标** ≥44×44；表格行整行可点；行内最多 2 个可点区域。
- **长名字**：单行截断 + 长按/`Tooltip` 显示全名；按钮文案不折行。
- **键盘弹出**：表单滚动到焦点；底部主操作上移，不被键盘盖住。

## 9. 设计语言

### 9.1 基座（不可另起一套）

- **组件**：shadcn/ui 官方件（经 `web/src/ui/kit/` 收编）；禁止页面内手写仿制。
- **图标**：lucide 单色线性，24×24 网格，1.8pt 描边，圆头圆角；颜色只取主题令牌。
- **颜色**：`web/theme.json` 的 Keel Zai Dark；正文 `foreground #d4d4d4`，底 `background #161616`，面 `panel #202020`，卡 `card #2b2b2b`，主操作 `primary #ffffff`。
- **材质**：solid-glass 家族令牌（`glass-rim` / `glass-inner` / `glass-edge` / `glass-shade` / `glass-lift`），只用于浮层、粘性条、选中态与需要分层的面板；不做彩色发光、渐变按钮、玻璃叠玻璃。
- **圆角**：卡 12、控件 6、胶囊 999；不混用 8/16。
- **字号地板（视觉评审后定）**：对象标题 30–32（唯一 H1）／节标题 18–20／正文 13–14／元数据 12／mono key 11／标签 ≥10.5；**禁止 9px 中文**（mono 编号、单位可 9–10）。非 disabled 文本对比度 ≥4.5:1；宁可删文案，不缩小字号。B 的层级靠字号对比与 hairline，不靠卡片；A baseline 用 20/13/11 + 卡片。
- **间距**：4px 阶梯（2/4/6/8/12/16/24/32/40）；页面节奏 24/32。
- **动效**：120ms 反馈、180ms 面板、260ms 大位移；只用于状态变化与空间连续性；不做装饰动画。

### 9.5 视觉红线（本 change 专属）

- **不做旧壳换皮**：B 不用左栏、不用卡片套卡片、对象页不用页签；层级靠字号（30–32/18–20/13–14/12/11）、留白与 hairline。
- **一屏一个实心主按钮**：脏状态保存主、试跑次；移动端「停止运行」描边 + 二次确认；「启动团队」只保留启动前检查里的一个权威入口。
- **字号地板**：对象名唯一 H1（30–32）；节标题 18–20；正文 13–14；元数据 12；mono key 11；禁止 9px 中文。
- **身份章例外**：桌面常驻 280 索引列（账号默认 / 权限组子页），不做 drill-in；页头不重复对象名。
- **设置可见**：页头齿轮 + 头像菜单双入口；不把设置藏进「更多」。
- **用词统一**：章节「记录」、节「变更记录」、能力「查看记录」；「审计」只做技术词。
- **不做账簿道具**：不铺纸张纹理、不做撕边/打孔/印章噪点；账簿是结构隐喻，不是拟物皮肤。
- **琥珀只做承诺**：未保存、待处理、签记用琥珀；不做装饰性黄色高亮。
- **mono 只做数据**：编号、key、时间、成本、印章标签；正文不用 mono。
- 不做「AI 味」：紫色/蓝色渐变、发光边框、玻璃叠玻璃、霓虹状态点、彩虹图标、装饰性 sparkles。
- 不做「程序员堆数据」：裸 JSON、裸表、无主次的字段墙；技术字段（key、run id、错误码）默认折叠在「技术详情」。
- 状态不只靠颜色：每个状态徽章都有文字；失败节点有图标 + 文案。
- 不用假数据糊弄：原型里的名字、时间、金额是设计样例并标注；生产界面必须来自真实接口，缺字段就补后端或标「待接入」。
- 不做假 chrome：不画浏览器地址栏、红黄绿窗口按钮、手机状态栏。

## 10. OpenDesign 使用记录

### 10.1 赛道与调性

- **赛道**：Convention（工具型 / 管理型产品）。证据：身份与权限是高后果、低娱乐性的管理面；用户要可预测、低认知负荷；创新视觉若脱离结构会变成装饰。
- **基调五刻度**（每项给证据，不给形容词）：
  - Energy：**quiet** —— 管理面，错误代价高；强调色只占 <10% 面积，主操作单一白色。

  - Weight：**medium** —— 正文 400，标题 500/600；深色底不用细体。
  - Seriousness：**solemn** —— 审计、权限、超管恢复；动效只做状态反馈（120/180ms），不做装饰。

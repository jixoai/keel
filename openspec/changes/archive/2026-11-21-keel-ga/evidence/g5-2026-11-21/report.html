Harness 自检项

  • seq contiguous from 1 on every session
  • every posted requestId committed exactly once
  • newest input answered; no input answered twice
  • read watermark covers every committed input
  • no unread-input flag left behind
  • no orphan tool results
  • every run converged (done/pending/failed)
  • every SIGKILL was followed by a counted runtime relaunch (restarts == faults)

断言失败

  • No assertion failures.

方法与口径

  • 规模与 2GB 合并：同一次运行同时覆盖 1000 SSE、64 并发 run、周期 1MiB 图片；2GB cgroup 复跑不再独立跑第二遍，避免“分开都能过、一起过不了”的假阳性。
  • 64 并发如何保证：64 个会话在 t=0 预填一条 input；runtime -runs 64，fake provider 每次固定 30s 延迟，保证 64 个 run 同时在执行。metrics keel_runs_active 每 250ms 采样，最大值必须恰为 64；随后队列排空、64 个 run 行全部 done。
  • 1000 会话在线：loadtest 创建 1000 个会话并保持 SSE；keel_streams_active 峰值必须 ≥1000。其余 936 个会话不发文本，避免把 1000 会话压测变成无界 run 洪泛。
  • SIGKILL 频率：cmd/chaos -mode kill -kill-every 30s -duration 600s，每次 SIGKILL 后立即重启并计数；结果 JSON 记录每个 kill 的时间戳/pid，平均值、最小值、最大值都写入报告。
  • 0 丢事件 / 0 重复回复：chaos 在静默期后读取每个会话的完整事件日志，校验 seq 从 1 连续、requestId 恰好出现一次、每个 input 至多一条最终回复、最新 input 必有一条最终回复、无孤儿 tool result、read watermark 覆盖最新输入、run 状态收敛。
  • 环境：macOS macOS-27.2-arm64-arm-64bit-Mach-O；Go go version go1.27.3 darwin/arm64；Docker 29.8.0；PostgreSQL PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2) on aarch64-unknown-linux-gnu, compiled by gcc (Debian 14.2.0-19) 14.2.0, 64-bit。混沌 runtime 跑在宿主进程（不包 cgroup），规模 runtime 跑在 2GB 容器；两者都不使用真实 provider 凭据。
  • 清理：专用数据库 keel_test_ga_g5 与 keel_test_ga_g5_chaos 在退出时删除，容器/端口/孤儿进程回收结果见下方 cleanup 证据。

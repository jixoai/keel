# Acceptance Criteria（验收标准）

本文是 `keel-harness-v2` 的收口门。判据全部可执行、可复跑、可被负控推翻；证据必须是**产物**
（报告/截图/命令输出/曲线），不接受自评文字。评审按项目纪律**只用子代理交叉复核，不启动 Codex**。

## 0. 口径

- **验收单元**：本 change 的 8 份 spec + 3 份梳理文档（`state-machines.md` / `plugin-boundaries.md`
  本文）逐条对表；未覆盖项必须显式登记并说明为什么不可验收。
- **预算（硬）**：后端整体（内核 + Harness + layerfs）**目标 ≤300MB，上限 ≤500MB**。
  **注意**：v1 实测基线是 1000 会话峰值 523.8–639.1MB——新上限**低于**既有基线，是待达标项，
  不是"已经满足"。
- **前端可分离**：NSH 客户端可跑在另一台机器 / 手机浏览器；其 surface VM 配额单独断言
  （默认单 surface 32–64MB），不计入后端预算，但不得回退。
- **负控**：每道门必须给出**能把它判失败**的构造（同 dump 双贴、坏 backend、超配额包等），
  否则该门不成立。

## G0 契约门

- **判据**：内核包不得 import 产品层（沿用 `internal/architecture` 断言）；插件不得访问同层
  内部状态（`plugin-boundaries.md` §9 五条判定规则可机检的部分必须机检）；无第二套插件运行时。
- **证据**：`go test ./internal/architecture/...` 输出 + 依赖图。
- **负控**：故意在 `internal/loop` 加一行 `import placement` → 必须失败。

## G1 状态机门

- **判据**：`state-machines.md` 的每台状态机有一张**转移矩阵测试**：合法转移通过，**非法转移
  被拒且留下拒绝事实**；静态检查证明不存在"仅内存态"的状态（每个状态可指到权威事实）。
- **证据**：每台状态机的测试清单 + 拒绝事实样例（事件流片段）。
- **负控**：直接构造非法转移（终态会话 resume、跨 epoch 双写、无 taskId 调用、超额放置）→
  必须被拒并可见。

## G2 恢复门（默认自愈）

- **判据**：`kill -9` 与容器重启后，**全部非终态 run 自动续跑，零人工干预**；中断的子代理
  **继续原任务**（不是新开替代者）；恢复次数/原因/所用配置可查；恢复不重复已提交副作用。
- **证据**：崩溃矩阵（模型流/工具/追加/压缩/capture/SSE 六格）+ 容器重启 E2E + 事件 seq 连续性
  断言 + 幂等断言（无重复最终回复、无重复工具效果）。
- **负控**：把 `resume.mode=never` 的会话纳入用例 → 它必须**不**自动恢复且列为待恢复。

## G3 幂等与冲突门

- **判据**：有副作用工具的重试只产生一次效果；文件写的前置条件不命中必须 `conflict` 并让 agent
  重读；webhook 重投不产生第二次会话；`resume` 同 requestId 幂等；`approve` 重复作答 409。
- **证据**：各幂等用例的账本片段 + 计数断言。
- **负控**：同一条 webhook 投递两次、同一审批答案提交两次 → 计数不得增长。

## G4 内存门

- **判据**：后端整体 RSS **≤300MB（目标）/ ≤500MB（上限）**，覆盖：单机组 `pack` × N 会话 × M
  并发 run、layerfs 大文件流式读写、capture 增量结算、1000 会话空闲态；**组 OOM 不扩散**；
  前端 surface VM 配额按声明执行（默认 32–64MB，关闭即卸）。
- **证据**：RSS 曲线（含峰值与稳态）、`lsof`/cgroup 读数、VM 装载/卸载前后对比。
- **负控**：写入大于配额的 blob 必须返回 `quota_exceeded`；打开/关闭重型面板前后内存必须回落。

## G5 任务门

- **判据**：每一次工具调用都有 `taskId`（缺失即拒）；任务树跨会话按 `parentTaskId` 拼得起来；
  fork 原点 `eventSeq` 精确（父之后的新写不可见）；资源只记 `(path, hash)` 引用，不复制字节。
- **证据**：任务面板截图（树 + 事件流 + 资源）+ 事件片段 + blob 引用计数。
- **负控**：无 `taskId` 调用、fork 后写父文件再读子会话 → 必须被拒/看不到。

## G6 插件门

- **判据**：安装/启用/停用/卸载**零残留**（工具、hook、触发器、UI 贡献、事件订阅）；缺依赖为
  `PENDING` 且原因可见；HMR 失败回滚且不打断进行中的 run；`extensibility.json` 缺失的官方插件
  发布被拒。
- **证据**：装载/卸载前后注册表 diff + generation 序列 + HMR 回滚日志。
- **负控**：卸载一个同时注册了工具与 UI 贡献的插件 → 模型面与界面必须同时干净。

## G7 UI 与槽位门

- **判据**：槽位由插件声明（Harness 无内置清单）；贡献只使用槽位允许的形态（chunk / package /
  iframe）；插件 UI 使用宿主 kit 与主题令牌（无硬编码色值/阴影）；`iframe` 显式标注非原生主题；
  TUI 中 `package`/`iframe` 显式不可用、`chunk` 可用；桥调用按插件能力裁剪，越权 `ERR_ACCESS_DENIED`。
- **证据**：web + 一个原生 target 的成对截图（含 TUI 降级态）；越权调用审计；主题切换前后截图。
- **负控**：给一个只允许 `chunk` 的槽位投 `iframe` 贡献 → 装配期必须拒绝并给出字段级原因。

## G8 创造模式门

- **判据**：**AI 现场写出一个 Native 插件**（chunk 槽位贡献），从聚合目录出发 → 生成包 →
  校验 → 审批安装 → 在客户端渲染出贡献 → 卸载无残留；缺文档/非法形态/硬编码令牌的包被拒且
  理由字段级可读。
- **证据**：AI 会话记录 + 生成的插件包 + 安装与渲染截图（web + 原生 target）+ 卸载后 diff。
- **负控**：故意在生成物里硬编码主题色、或贡献到不存在的槽位 → 必须安装前被拒。

## G9 有界门

- **判据**：工具输出有界（head/tail + blob 引用，200MB 输出不整段进内存/账本）；并发槽位满时
  明确排队（带 ETA）或 429（带 `retry_after`），不静默丢弃；每组后台作业有上限，超限拒绝新作业
  且不 kill 已有。
- **证据**：大输出用例的 RSS 曲线 + 429/排队响应样例 + 作业上限用例。
- **负控**：连续提交超过上限的作业 → 必须被拒且既有作业存活。

## G10 资源回收门

- **判据**：任何测试/走查结束后**零孤儿**：无残留进程（含 sidecar、外部运行时、后台作业）、
  无残留监听端口、无残留 VM；每步给出回收证据。
- **证据**：`ps`/`lsof` 前后对照 + 端口台账核对（`.agents/docs/PORT.md` 纪律）。
- **负控**：故意让一个 sidecar 脱离进程组 → sweep 必须能回收或明确标记 `lost`。

## G11 交付面门

- **判据**：E2E 报告为 **HTML 图文文档**（每步截图 + 做了什么/预期/实际断言/关键日志），落
  `.agents/reports/<group>/<fileName>/` 并随主仓入库；**每个改动过的文件**在审计清单里有对应
  页面/状态（视觉文件必须 before/after 成对截图），`UNCOVERED=0`；交叉复核由子代理完成。
- **证据**：`report.html` + 覆盖表 + 复核结论（评分与阻塞项）。
- **负控**：抽查一个未截图的改动文件 → 审计必须判 UNCOVERED。

## 附：门的依赖顺序

```
G0 契约 → G1 状态机 → { G2 恢复, G3 幂等, G5 任务 } → { G4 内存, G6 插件, G7 UI, G9 有界 }
        → G8 创造模式 → G10 资源回收 → G11 交付面
```

前置门未绿时，后续门的结果不作为验收依据（避免"在坏地基上测得好看"）。

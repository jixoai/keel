Scope delivered
- agent tool actions: spawn / fork / resume / cancel / list / status (no not_implemented).
- fork: eventSeq origin validated against the parent ledger; new session; durable fork
  fact on sessions (parent, originSeq, tree hash, parent config/tool snapshot);
  new card with parentTaskId = origin card; parent selection inherited by default.
- ledger prefix: read-time union of the parent log (seq <= origin), injected with
  negative synthetic seqs; no parent events copied; inputSeqs stays child-only.
- file prefix: session_snapshot tree hash resolved O(1); read/write/edit/list/materialize
  use an overlay; capture does not copy unchanged inherited manifest rows; inherited
  blobs stay referenced by the child snapshot.
- slots: child input goes through the same placement Gate/admission as any native run;
  full group/tenant -> typed CapacityError; HTTP 429 + Retry-After (ceil, same as W2);
  model tool -> capacity_exhausted + retryAfterMs. No queue (W2 decision: explicit 429).
- return: structured result + artifact refs (tool trail, bash stdout/stderr blobId,
  fs.write path/hash, fs.capture treeHash; bounded 256); parent card task.note via
  NoteSubagentFinished, idempotent, lands on the child card's parentTaskId.
- resume: same session/run/card; only failed or lease-expired running runs requeue;
  resume.attempt keyed by requestId (idempotent); optional selection/agentId override
  travels in resume.attempt (no new user.message); W2 run snapshot values asserted on
  the recovered attempt.
- owed-turn fix: non-transcript bookkeeping kinds (resume.attempt, fs.*, config.*,
  placement.*, supervision.*, guardrail.*, notification.*) no longer hide an owed input.

Residual (honest)
- config.toml/loadout revision inheritance is partial: the fork freezes the parent
  attempt's configHash/toolManifestHash/anchor and inherits its selection, and resume can
  override the binding; a child run still pins the current generation at claim time.
  Forcing a specific old loadout revision needs per-session loadout pinning (W2/loadout).
- Queue + ETA is not implemented; over-limit is explicit 429 + Retry-After (W2 scope).
- agent.status after a process restart is registry-only (durable parent link exists, but
  the record is rebuilt from the child ledger only for resume/cancel authorization).

P1 fix (B-axis review, 2026-11-21)
- Fork side effects are now compensated when the first input never commits: the run slot
  and placement are released, the fork fact is cleared, the child card is closed
  (converged, not left open), and the child session is deleted when empty or archived
  when it carries the closed-card ledger fact. A failure after the input commit is not
  rolled back (the durable child run keeps its fact/card).
- ForkCard's card id is the child's deterministic initial card; the create key derives
  from the caller's stable callID. A closed card is reopened on retry. N capacity
  refusals followed by a success leave exactly one child card and one input.
- Tests: TestForkCapacityRetryConvergesToOneCard, TestForkCardIsIdempotentAndReopens,
  TestTasksPluginDoesNotRelinkForkedCards; existing fork/resume tests unchanged.

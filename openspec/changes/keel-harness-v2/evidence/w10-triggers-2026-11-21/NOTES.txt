Scope delivered

1. HMAC (webhook)
- TriggerSpec.WebhookSecret is a per-trigger HMAC-SHA256 key, json:"-" (never
  serialized): internal/agentext/triggers.go:87. WebhookSecretEnv names the
  env var resolved once at Register; an empty/unset value leaves the trigger
  fail-closed.
- Canonical signed bytes: v1\n<tenantId>\n<triggerId>\n<timestamp>\n
  <idempotencyKey>\n<rawBody>; headers X-Keel-Timestamp (unix seconds) and
  X-Keel-Signature: sha256=<hex>. Constant-time compare via hmac.Equal; the
  timestamp must be inside webhookToleranceSec (default 300s, max 86400s):
  internal/agentext/triggers.go:1120 (verifyWebhook).
- Fail-closed: unconfigured trigger -> ErrTriggerWebhookUnconfigured (HTTP 403);
  missing/bad/stale signature -> ErrTriggerWebhookUnauthorized (HTTP 401); no
  turn is started and every refusal is audited status:"rejected" with a
  category only (no secret, no received signature).
- HTTP reads the exact body once before decoding, so re-marshalling cannot
  break a signature: internal/agentapi/ext.go:121. Signature headers select
  reason=webhook and cannot be downgraded by a body that says manual
  (internal/agentapi/ext.go:96-103).
- The example plugin uses KEEL_EXAMPLE_WEBHOOK_SECRET via WebhookSecretEnv
  (cmd/keel/serve.go); without it the trigger stays fail-closed for signed
  deliveries but the authenticated manual fire route still works.

2. Dedupe / catch-up
- Same-key serialization is retained. In-process duplicate deliveries return
  deduped:true and audit status:"deduped"; across restarts the kernel requestId
  dedupe returns fired+deduped:true, so no second user.message.
- Durable cursor table trigger_state(tenant_id, trigger_id, last_scheduled_at,
  last_fired_at, last_status, updated_at), RLS tenant table:
  internal/store/schema.sql:1078, internal/store/rls.go:89,
  internal/store/triggers.go:19-79 (Load/Save; monotonic last_scheduled_at).
- On registration/restart the engine loads the cursor and replays missed
  windows: internal/agentext/triggers.go:846 (resume), :929 (catchUpPlan),
  :998 (saveCursor). Bounds: only the newest catchUpLimit windows (default 3),
  lookback catchUpWindow (default 24h); older windows are coalesced into one
  status:"skipped" audit entry. Catch-up fires use the same stable idempotency
  key sched:<id>:<unix> as normal schedule fires and reason:"catchup".
- A window that hits the concurrency cap is not advanced in the cursor, so a
  restart can retry it instead of losing it silently.

3. Per-trigger concurrency + initial task card
- MaxConcurrent (default 1) is a non-blocking per-trigger slot:
  internal/agentext/triggers.go:1089 (tryAcquire). Above the cap the fire is
  refused with ErrTriggerBusy -> HTTP 429 + Retry-After: 1 and a
  status:"throttled" audit (internal/agentapi/ext.go:141). No unbounded queue.
  Idempotent retries of the in-flight key wait for the key's first fire and
  then hit the dedupe branch instead of being throttled.
- A successful fire immediately creates the session's initial task card via
  tasklog.EnsureCard: internal/agentext/triggers.go:663. The response carries
  taskCardId; a card failure is visible as taskCardError but does not roll back
  the committed turn (the first tool call still has the lazy path).

4. Observability
- GET /v1/triggers now exposes fires/failures/dedupes/throttled/rejected/
  skipped, inFlight, webhookConfigured, lastScheduledAt and the recent 20 audit
  entries (fired/failed/deduped/throttled/rejected/skipped), never the secret.
- docs/HARNESS.md §3.1 documents the signing string, headers, window,
  fail-closed behavior, catch-up bounds, 429 semantics and card ownership.
- The change spec gained three requirements (Webhook 投递真实性 / 触发器去重与
  漏跑补偿 / 触发器并发与归属) in specs/harness-core/spec.md.

Known limits / not done
- HMAC keys are resolved from a direct spec value or a named environment
  variable. There is no operator settings UI/DB secret store for trigger
  secrets in this change; the secret must be provided by the hosting plugin or
  env.
- Manual fires remain authenticated-but-unsigned by design; the reason flag is
  provenance, and the route's tenant authentication is the boundary. A future
  ingress that exposes webhook URLs to third parties should require signature
  headers there.
- Catch-up is best-effort: a DB outage at resume logs a warning and schedules
  from now (the next fire persists a fresh cursor); a window that hits the
  concurrency cap is retried only on the next restart, not queued.
- The trigger engine's in-memory fire history (4096 keys) is an optimization;
  cross-restart dedupe is the kernel requestId, not this map.

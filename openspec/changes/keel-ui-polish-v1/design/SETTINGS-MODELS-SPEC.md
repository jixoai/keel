# Keel Harness · 模型接入页设计规格

版本 1.0 · 桌面优先 · 深色中文界面 · 配合 `settings-models.html` 阅读

设置 › 模型接入是一页两级结构：**列表页**（部署默认 + Provider 卡片 + 只读导出）与**编辑对话框**（添加 / 配置单个 Provider）。本文给出的数值即原型中卡片、对话框、表单与状态条的实际实现值，与代码逐项一致。

---

## 1. 设计定位

| 项目 | 定义 |
|---|---|
| 产品表面 | AI 员工操作系统的设置页；桌面优先，1080px 内容宽 |
| 使用者 | 需要接入模型供应商的工程与管理岗位；关注「改了哪一家、是否生效、凭据放在哪」 |
| 核心模型 | 部署默认只决定新会话；每家 Provider 独立维护协议、地址、凭据与模型 |
| 语气 | 仪器式、克制、可核对。先把默认与接入分开，再逐家核对 |
| 强调色 | 暖白 `#F5F1E8`，只用于主按钮、焦点环、选中状态胶囊与「当前」标记 |
| 语义色 | 错误 `#F08C7C`、警告 `#E6B76A`、成功 `#8ED3AC`，只出现在状态与校验中 |
| 背景 | 中性近黑 `#0A0A0B`；不使用暖米底、渐变、玻璃拟态与霓虹光晕 |

本页沿用 `DESIGN-SPEC.md` 的令牌、字号阶梯与 4px 栅格，不引入新的视觉语言。

## 2. 两级结构与导航规则

### 2.1 层级

| 层级 | 内容 | 宽度 |
|---|---|---|
| 一级：列表页 | 状态条 → 页头 → 当前默认模型 → Provider 卡片网格 → 高级：原始配置（折叠） | 内容 1080px |
| 二级：编辑对话框 | 接入（名称 / 协议 / 地址 / 凭据）→ 模型列表 → 底部动作 | 560px |

```text
设置 › 模型接入
├─ 一级：列表页
│  ├─ 当前默认模型 ──「更换」→ 模型菜单（不开新层）
│  ├─ Provider 网格 ──「配置 →」──────────────┐
│  └─ 高级：原始配置（折叠，只读）            │
└─ 二级：Provider 对话框 ←────────────────────┘
   ├─ 接入：名称 / 协议 / 地址 / 凭据引用
   ├─ 模型：chips（可删、可点名称修改）+ 输入 + 添加 / 更新
   └─ 底栏：删除该 Provider / 取消 / 保存并生效
```

一级不含任何表单；二级不重复列表信息。默认模型块只提供「更换 / 刷新」，不进入二级。

### 2.2 进入与返回

| 动作 | 层级变化 | 落点与反馈 |
|---|---|---|
| 卡片「配置 →」 | 一级 → 二级（编辑） | 标题「配置 {名称}」；焦点落在服务地址；返回焦点记录为该卡「配置 →」 |
| 「添加 Provider」（列表区右上或空态卡片） | 一级 → 二级（新建） | 标题「添加 Provider」；焦点落在显示名称；返回焦点记录为「添加 Provider」 |
| 「取消」/ 关闭 × / Esc | 二级 → 一级，不写入 | 焦点回到触发按钮；若本次有修改，toast「已放弃未保存的修改」 |
| 「保存并生效」 | 二级 → 一级，写入成功 | toast「已保存并生效」；焦点回到该 Provider 卡片的「配置 →」（新建即新卡片） |
| 「删除该 Provider」 | 二级内进入确认，不叠加第三层 | 底栏替换为「保留 / 确认删除」；焦点落在「确认删除」 |
| 确认删除 | 二级 → 一级，移除成功 | toast「已删除 {名称}」；焦点回到「添加 Provider」；删最后一家时列表切到「未配置」空态 |
| 顶部状态胶囊 | 关闭二级并切换页面状态 | 仅用于规格审阅，产品内不存在该控件 |
| 「刷新」 | 一级 → 加载中 → 已配置 | 约 900ms；toast「已刷新 Provider 状态」；焦点回到「刷新」 |

### 2.3 不关闭的情况

- **保存中**：Esc 不关闭；关闭 ×、取消、删除按钮均为 `disabled`，避免误以为已生效。真实保存约 900ms，「保存中」预览 1.4s 后自动落到「已配置」。
- **删除确认中**：Esc 退回编辑底栏，焦点回到「删除该 Provider」，不直接关闭。
- **点击遮罩**：不关闭。只有显式「取消 / × / Esc」才退出，防止误丢地址与凭据引用。
- 关闭不拦截草稿（字段少、可快速重填）；用 toast 告知放弃，而不是再弹一层确认。只有删除有二次确认。

### 2.4 保存后的列表行为

- 卡片按原位置重渲染，不整页刷新、不滚动跳顶。
- 状态徽标按凭据推导：有凭据 → **已配置**；无凭据且原状态为「不可用」且地址未变 → **不可用**；其余 → **未配置**。
- 若默认模型指向的 Provider/模型已不存在，自动回落到第一家已配置 Provider 的第一个模型；全部删除则默认模型块切为空态文案。

## 3. 画布与断点

| 断点 | 行为 |
|---|---|
| ≥901px | 内容 1080px 居中，左右内边距 32px；Provider 两列 |
| ≤900px | 内边距收为 24px；Provider 改单列；状态提示行独占一行、左对齐 |
| ≤760px | 仅顶栏：高 56px，隐藏品牌后缀、分隔线与右侧 `MODELS · PROVIDERS` |
| ≤640px | 移动布局：内容内边距 16px；状态胶囊 44px 单行横向滚动；默认模型块单列；对话框四周留 8px（可用宽 = 视口 − 16px） |

断点分两层：**760px 只处理顶栏**，**900px 处理卡片列数**，**640px 才整体收缩**。641–900px 仍使用桌面顶栏与两列以外的桌面组件尺寸。

参考视口：

- 1440×1200：顶栏、状态条、页头、默认模型块与两行 4 张卡片可在一屏内完整看到，页面无横向滚动。
- 900×1000：单列 4 张卡片；状态提示行换到胶囊下方。
- 390×844：单列；状态胶囊可横向滚动；对话框宽 374px（390 − 16 外边距）。

## 7. 组件规范

### 7.1 默认模型块

- 结构：字标（Provider 首字母）→ 眉标「当前默认模型」→ Provider 名 → 模型名 + 思考档位胶囊 → 说明「部署默认 · 新会话自动使用 · 上次刷新 {时间}」。
- 动作：主按钮「更换」、次按钮「刷新」；「更换」在无已配置 Provider 时 `disabled`。
- 菜单：`min(340px, 100vw − 48px)`，最大高 340px，按 Provider 分组。当前项带勾选；底部注记「只列出已配置 Provider 的模型。选择后对新会话生效。」
- 菜单打开后焦点进入第一项；Esc 关闭并回到「更换」；点击菜单外关闭；窗口 resize 时关闭。
- 空态：降级为 `--surface` 底、单列、一行说明，不显示字标与动作。

### 7.2 Provider 卡片

- 三行：标题行（圆形字标 + 名称 + 地址 + 徽标）/ 模型胶囊 / 底行（协议 · 凭据 · 配置按钮）。
- 地址等宽 10.5px，可任意断行；凭据以 `<code>` 呈现引用；`127.0.0.1` / `localhost` 地址显示「无需凭据」，Ollama 另加「本地服务未启动」。
- 「不可用」时模型胶囊改虚线描边、文字降为 `--ink-3`；徽标为警告色。
- 卡片整块不可点击；只有「配置 →」进入二级，避免误触。

### 7.3 编辑对话框

- 三段式：头部（标题 / 副标题 / 关闭）× 主体（可滚动）× 底栏（固定）。
- 主体分「接入」「模型」两区，中间 1px 分隔线。
- 接入字段：显示名称（仅新建）、接口协议、服务地址、凭据引用。
- 协议选项（仅三项）：**OpenAI 兼容** / **Anthropic Messages** / **OpenAI Responses**，默认 OpenAI 兼容。
- 凭据写法格常驻展示三种引用，只读、不可聚焦。
- 模型区：计数「n / 12」；已有模型以 chips 呈现，每枚含名称按钮（点击进入修改）与 24px 圆形删除按钮；下方为「输入模型名称」+「添加」。
  - 输入后点「添加」或按 Enter：追加 chip，输入清空，焦点留在输入框。
  - 点 chip 名称：名称填入输入框，按钮变「更新」，出现「取消修改」；提交后原位替换。
  - 删除允许减到 0，此时显示「还没有模型。在下方输入名称后点「添加」。」；保存时再校验至少 1 个，避免边填边报错。
  - 上限 12 个，达到上限后「添加」禁用并提示「最多 12 个模型。」
- 底栏：编辑态左侧红色文字按钮「删除该 Provider」；右侧「取消」「保存并生效」。
- 删除确认：底栏替换为「删除 {名称}？」+「该 Provider 的 N 个模型将从默认选择中移除。此操作不可撤销。」+「保留」「确认删除」。不新开对话框。

### 7.4 表单与校验

| 字段 | 规则 | 校验文案 |
|---|---|---|
| 显示名称 | 新建必填，≤40；与现有 Provider 不区分大小写重名即拒绝 | 「请填写 Provider 显示名称。」/「已有同名 Provider，请换一个名称。」 |
| 接口协议 | 三选一，默认 OpenAI 兼容 | — |
| 服务地址 | 必填，`http://` 或 `https://` 开头，不含空格 | 「请填写服务地址。」/「地址需以 http:// 或 https:// 开头，且不能包含空格。」 |

## 9. 三步接入路径（逐字文案）

### 第一步：从列表进入

- 点哪里：Provider 区右上「**添加 Provider**」；空态时点空态卡内的同名主按钮。
- 看到什么：560px 对话框，标题「**添加 Provider**」，副标题「**填写接入信息；保存后立即出现在 Provider 列表。**」，焦点在「显示名称」。

### 第二步：填写接入信息

| 顺序 | 标签 | 控件与占位符 | 常驻提示 |
|---|---|---|---|
| 1 | 显示名称（必填） | 文本框，`例如 Groq` | — |
| 2 | 接口协议 | 下拉，默认「OpenAI 兼容」 | — |
| 3 | 服务地址（必填） | URL 文本框，`https://api.example.com/v1` | 填写包含版本路径的完整地址，例如 https://api.deepseek.com/v1。 |
| 4 | 凭据引用 | 文本框，`env:PROVIDER_API_KEY` | 只填引用，不要粘贴明文密钥。本地服务可留空，保存后状态为「未配置」。 |

- 回到列表：toast「**已保存并生效**」；新卡片出现在网格末尾，徽标为「已配置」（有凭据）或「未配置」（无凭据）；若此前没有默认模型，自动选新 Provider 的第一个模型作为默认。

## 13. 可访问性与键盘路径

### 13.1 键盘

- **列表页 Tab 顺序**（DOM 顺序）：状态胶囊 → 「更换」→「刷新」→ 各卡片「配置 →」→「添加 Provider」→ 高级折叠标题。
- **默认模型菜单**：打开后焦点进入第一项；Tab 在菜单项间移动；Esc 关闭并回到「更换」；点击外部关闭。菜单项为真实按钮，当前项 `aria-pressed="true"`。
- **对话框 Tab 顺序**（已实测）：关闭 × → 显示名称（仅新建）→ 接口协议 → 服务地址 → 凭据引用 → 模型 chip 1 名称 → chip 1 删除 → …… → 模型输入框 → 添加 / 更新 → 取消修改（仅修改时）→ 删除该 Provider（仅编辑）→ 取消 → 保存并生效 → 回到关闭 ×。
- **Enter**：模型输入框内按 Enter 添加/更新模型，不提交表单；其余文本输入框内按 Enter 触发保存；下拉与按钮使用各自默认行为。
- **Esc**：正常编辑时关闭且不写入；保存中无效；删除确认时退回编辑底栏并把焦点交给「删除该 Provider」。
- **焦点回交**：关闭后回到触发的「配置 →」或「添加 Provider」；保存成功后回到该卡的「配置 →」；删除成功后回到「添加 Provider」。
- **校验焦点**：提交失败时聚焦第一个 `aria-invalid="true"` 的字段；删除确认时聚焦「确认删除」。

### 13.2 语义

- 对话框：原生 `<dialog>` + `showModal()`，`aria-labelledby="editorTitle"`、`aria-describedby="editorSub"`；保存中主体 `aria-busy="true"`。
- 状态胶囊：`<button aria-pressed>`；提示行 `aria-live="polite"`。
- 错误汇总 `role="alert"`；字段错误用 `aria-describedby` 指向 `#error-{field}`；模型错误在模型编辑区下方整体呈现，并关联模型输入框。
- 图标按钮均有 `aria-label`（「关闭配置」「删除模型 {名称}」「编辑模型 {名称}」）；模型输入框 `aria-label="新模型名称"`；模型列表为 `ul`，标签「已添加的模型」；装饰图标 `aria-hidden="true"`。
- Toast `role="status"` + `aria-live="polite"`。
- 焦点环：全局 2px `--accent`、偏移 2px；控件内偏移 1px。
- 触控：≤640px 主要控件 ≥44px；相邻按钮间距 ≥8px。
- 动效：`prefers-reduced-motion: reduce` 下动画与过渡降为 0.001ms，骨架停止闪烁。

## 14. 内容与实现边界

- 单文件静态页面：0 个外链脚本、样式、字体或图片；图标为 16px 网格内联 SVG，线宽 1.4px。
- 顶部「状态」条是规格审阅工具，不属于产品界面；产品内不存在这组胶囊。
- 保存为前端模拟：真实保存 900ms；「保存中」预览 1.4s 后自动完成并落回「已配置」，避免审阅时被困在不可关闭的模态里。
- 数据不落盘：刷新页面回到种子数据。种子为 4 家 Provider（Magpie、DeepSeek 已配置；Anthropic 未配置；Ollama 走 OpenAI 兼容的本地 `/v1`、无可达服务），默认模型 DeepSeek V3.2。
- 凭据只保存引用（`${NAME}` / `env:NAME` / `secret:NAME`），界面任何位置都不出现明文密钥；「高级：原始配置」为只读 JSON 导出。
- 「刷新」只模拟重新读取状态（900ms → 已配置），不发起网络请求。
- 默认模型切换只影响展示与「新会话」文案，不与真实会话引擎联动。
- 新建 Provider 的 id 由名称转 slug（小写、连字符、重名加 `-2`），仅用于 DOM 关联与焦点回交。
- 页面不提供批量导入、连接测试按钮或模型能力编辑；这些不在本轮范围内。

## 2. 关键设计说明

- **账本零新增 kind**：`internal/mcphost` 不 import `kernel`/`store`；`mcp.progress` 只是
  `agentext.Partial.Type`（瞬态通道），不是 `kernel.EventKind`。`TestNotificationStorm...`
  对 `kernel.Kinds()` 前后集合做断言。
- **与产品 SSE 隔离**：`internal/architecture/mcp_events_isolation_test.go` 用真实 import 图断言
  `mcphost` 不 import `httpapi`/`agentapi`，`mcp` 不 import `mcphost`/`httpapi`。
- **run 边界**：v2 模型面工具清单恒定（11 内建 + 聚合 `mcp`），目录变化体现在聚合工具的
  list/describe/call 上；因此边界由 attempt 级目录快照实现。当前 attempt 冻结、下一 attempt
  看到新目录；被删除的工具名在下一 attempt 返回 `not_found`。
- **失败保面**：`Manager.RefreshServer` 只替换 `*Server` 指针（旧值不可变），失败时复制旧值并只
  写 `CatalogueError`；Registry.Refresh 继续使用旧 `server.Tools`，app 走既有 keepPrevious 规则。
  `/v1/mcp/servers` 的 `catalogueError` 与 `catalogue.list`/`catalogue.refresh` 审计行可见。
- **legacy 兼容**：`Client` 默认路径（无回调）逐字不变；legacy GET 流、`Last-Event-ID` 退避重连
  代码未改，只新增 `OnReconnect` 通知宿主做全量重算。

## 3. 复核修复（2026-11-20，独立双轴复核）

- **P1 请求域通知不被 listen 吞**：`Notification` 增加非序列化的 `Source` 传输元数据；HTTP
  `consumeResponseStream` 给响应流帧标 `response:<request-id>`，内存传输保持该元数据。客户端的
  路由只对「来源就是 listen 流」的未打标帧按违规诊断；tools/call 响应流、stdio、legacy GET 等
  来源的未打标 progress/cancelled/message 走全局路径。`TestClientListenAckFilterAndTagging`
  已改为显式设置流来源，并新增 `TestClientRequestDomainNotificationsNotSwallowedByListen`。
- **P2-c progress 有界**：`PublishMCPProgress` 对 `Message` 去控制符并按 rune 截断 256B；
  `TestMCPProgressMessageIsBounded`。
- **P2-f 日志采样**：客户端对 untagged/队列满/ack 前/未 opt-in 四类协议告警每连接每秒最多 1 条，
  合并为 `(suppressed=N)`（假时钟 `TestClientDiagnosticSampling`）。
- **P2-g 短命流退避**：ack 后 <5s 即结束的连续流不重置退避；第 3 次起 1s→2s→4s…（上限 30s）
  （`TestEventsShortLivedListenStreamsBackOff`）。
- **Reconnect 后 listen 重评估**：`ConnectOptions.ServerReconnected` 在 `Manager.Reconnect` 成功后
  通知 `Events.ServerReconnected`，取消旧 supervisor 并对新连接按 era 重新决定是否 listen
  （`TestEventsServerReconnectedStartsListen`）。
- **P2-b HTTP 关流即取消**：`TestHTTPListenCloseCancelsServerStream` 断言测试服务器观察到请求
  上下文取消。
- **文档**：metrics 头注释改为 31 Prometheus wire series（24 logical samples + MRTR 直方图
  展开为 8）；tasks/notes 登记 prompts 当前无内容存储。

## 4. 偏离 / 未决（诚实列出）

1. **P4.3 生产启用等待 P5**：`Events.listenFor` 默认仅对 `protocolVersion >= 2026-07-28` 启动
   listen；P4 的客户端/监督器/测试全部就绪，但 `SupportedProtocolVersions` 加入 2026-07-28 与
   era 探测在 P5.4。legacy 服务器维持 GET 流（符合 spec「legacy 重连兼容」）。
2. **`mcp_mrtr_rounds` 只有注册与单测**：MRTR 执行器是 P5.2，P4 只固定 series（histogram 存在，
   计数为 0）。
3. **bridge 帧指标按 HTTP 代理面计数**：`mcpAppGate` 每请求记 `in`，release 记 `out`（含拒绝
   路径）；浏览器端 64 KiB/200 fps 的本地帧没有单独计数（P3.8 的浏览器桥实现不在服务端可观测
   范围内）。
4. **目录快照缓存 256 个 attempt**：崩溃进程的 attempt 不会显式回收，靠 LRU 上限兜底（不随会话
   数增长；单条只持有不可变 `*Server` 指针）。复核指出快照可能持有已断连的旧 client；这是
   attempt 冻结语义的既有代价，登记 backlog，本批不改。
5. **prompts 内容刷新留 P5/P6**：仓库当前没有 prompts 内容存储/缓存，`prompts/list_changed`
   只触发注册面重算与 generation；真正的 prompt 内容刷新在 P5/P6 补，不在 P4 假装完成。
6. **未做**：P5 的 MRTR 执行器/era 探测/update-model-context、P6 浏览器 E2E 与验收报告（任务书
   明确不在本 lane）。

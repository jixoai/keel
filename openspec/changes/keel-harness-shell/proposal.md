# Proposal: keel-harness-shell（用 UI Kit 重建 Harness 外壳与全部页面）

## Why

界面被 Owner 判为「程序员视角的工具」：布局手搓、比例随意、配置散落、产品里还有演示模式。
`keel-ui-kit` 提供了经过门禁的组件与布局块之后，本变更负责把 Harness 的**每一个页面**重建到
这套块上，并按 zcode 的信息架构组织配置与状态。

## What Changes

1. **应用外壳**：`WorkspaceShell`（侧栏 + 主区 + 右侧状态栏），窄屏单列/抽屉；标题栏 h-12；
   Command Palette（Cmd/Ctrl+K）承载全局动作（会话切换、模型切换、设置、插件）。
2. **会话列表 = Sidebar block**：搜索、新建、会话行（标题/预览/时间/状态徽标）、底部连接状态；
   无「演示数据/切到演示」入口。
3. **对话面**：
   - 头部：标题、模型 chip（本会话）、状态词（就绪/等待确认/运行中/…）、右栏开关；
   - 轮次：用户气泡、助手内容、工具家族卡（摘要行 + 折叠详情、结果先行）、审批/问询卡、
     错误横幅（输入框上方）、引导行（流末尾）、身份行（provider/model）；
   - 输入区：`ComposerDock`（多行、附件、队列/引导、停止/发送、模式切换）；
   - 滚动：吸底/脱离意图、每会话记忆、回到底部圆钮；
   - 右侧状态栏（≥1280）：本会话的运行事实（模型/思考档/用量/插件/工具），可收起。
4. **设置面**：`SettingsShell`（rail 68→268 + 内容卡 + 面包屑 + max-w-4xl），分区：通用 / 外观 /
   模型与 Provider（结构化表单 + 高级折叠里的原始文档）/ 密钥 / 插件（清单、状态、安装入口、
   触发）/ 快捷键 / 关于。**原始 JSON 只在高级折叠里**，不再是主界面。
5. **插件面**：插件列表（已装/可装/创造模式入口），插件 UI 通过 WebView 承载（见 `keel-plugin-core`），
   TUI 下点击插件 = 打开浏览器（`openUrl`）。
6. **演示模式退场**：fixture 传输保留为开发内部能力（`?fixture=1` 或 env），产品 UI 不出现任何
   「演示/demo/fixture」字样与开关；连接失败时显示真实错误与重试，不伪装成演示。
7. **TUI 同等结构**：同一份代码在终端渲染时使用同一套块（宽度/断点按终端格数适配），
   插件 UI 不可内联渲染 → 打开浏览器。

## Non-Goals

- 不新增业务功能（会话/审批/工具/插件的行为不变）。
- 不改变服务端 API（除插件 UI 路由，那在 `keel-plugin-core`）。
- 不做 zcode 的 dnd 标签排序与终端面板。

## Impact

`web/` 全部 screens 重写/重组；`App.tsx` 外壳；`web/src/data/*` 仅做必要的状态补齐
（例如右侧状态栏需要的会话事实）。产品不再暴露 fixture。
